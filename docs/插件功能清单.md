# 插件功能清单

本文档是兼容入口。当前功能清单的事实来源请阅读：

- `.ch/docs/product-specs/FEATURE_INVENTORY.md`
- DeepSeek Harness（`dsh`）已接入，顺序为 `codex`、`claude`、`opencode`、`grok`、`dsh`。主路径是 `dsh --profile acp`。配置页范例包含空 `apiKey`，默认模型 id 是无前缀的 `deepseek-v4.1-flash`；复制后选择实际 API 类型并填入正确的 `baseURL` 和 `apiKey` 即可，前提是服务兼容所选协议并接受这个精确模型 id。若服务要求其他 id，需同步调整 `models[].id` 和 `acpModel`。模型 id 不会自动增删前缀，执行时还必须由 ACP 广告。凭据默认引用 `SINITEK_DSH_API_KEY`，也支持在 profile 根级直接配置 `apiKey`；明文仅保存在本机私有配置和备份中，运行 patch 不包含密钥，直接配置优先于外部环境变量。Skills 市场目标共七个，顺序保持 Claude、OpenCode、Grok、Codex、DSH、Kimi Code、ZCode。Skills 根和 `AGENTS.md` 规则链已接入。未配置模型不能执行，模型下拉不提供空的“默认”占位项，无已选模型时直接使用配置里的第一个模型。usage 缺失不显示为 0，adapter-fallback 不是服务容量。默认验证模型在面板提供 DeepSeek `low`、`high`、`xhigh`、`max` 四档；其他自定义模型需显式声明能力，runner 只下发 ACP 当前公布值。原生 compaction 明确不支持。真实权限请求和图形 Extension Host 点击验收未验证，不得虚报。配置页同时提供 JSON 文本和可视化两种模式，编辑同一份完整 JSON。已接受的额外顶层字段和模型对象字段会保留。未验证字段和嵌套密钥在验证阶段拒绝，且不写入运行 patch。provider 只读。`baseURL`、模型 id、`apiKeyEnv` 和根级 `apiKey` 可编辑；`apiKeyEnv` 仍固定为 `SINITEK_DSH_API_KEY`。`models` 按已安装 schema 保持有序数组，可新增、编辑、删除并选择当前 `acpModel`。详情区不显示激活状态。事实来源见功能总表与 `.ch/docs/references/dsh-custom-provider-contract.md`。
- 默认验证模型的 AI 对话面板直接显示 DeepSeek 思考力度原始 value：`low`、`high`、`xhigh`、`max`；隐藏 `off` 和空 value，其他自定义模型仅在 profile 显式声明思考能力后显示，实际运行仍以 ACP 广告值为准。
- Kimi Code（`kimi-code`）已接入，顺序为 `codex`、`claude`、`opencode`、`grok`、`dsh`、`kimi-code`；交互主路径是 `kimi acp`，`args.kimi-code` 只允许 `--region`。官方包 `@moonshot-ai/kimi-code`（bin `kimi`，要求 Node >= 22.19.0）。安装有两条官方路径：脚本 `curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`（Windows `irm https://code.kimi.com/kimi-code/install.ps1 | iex`，无需预装 Node）与 npm `npm install -g @moonshot-ai/kimi-code`；插件自身的安装/修复入口只用可回滚的 `npm install -g @moonshot-ai/kimi-code@latest`（本机实测 2.3.2）。版本检查 `kimi --version`，配置自检 `kimi doctor config`。配置是 `~/.kimi-code/config.toml`（TOML，snake_case，`KIMI_CODE_HOME` 可改目录），默认模型别名 `subcoco/kimi-k3.1-pro`；凭据只来自该文件的 `api_key` 或 `api_key_env`，插件不注入密钥并剥离其它 CLI 的 `*_API_KEY`。免审批是真实能力，但官方 `--auto` / `--yolo` 与一次性任务的 `-p` 互斥，因此只能写 `default_permission_mode = "auto"`（默认新范例即 `auto`），插件不拼这两个参数。思考档只下发 ACP 广告值，不改写 `ultra`；广告集合由模型表的 `capabilities` 与 `support_efforts` 决定，未声明时 ACP 没有 `thinking` 选项。默认配置文本与配置页范例已写入 `capabilities = ["thinking", "tool_use"]` 与完整 `support_efforts`，可视化编辑器可编辑且留空不删除，面板思考下拉按 ACP 实际广告值刷新（只有 `off` / `on` 时禁用）。主/子模型复用插件通用角色选择，候选只取当前配置的模型；子任务未单独选择时先回落到普通对话所选模型、再回落到 `default_model`。上下文窗口展示取 `usage_update.size`，即配置声明的 `max_context_size`，不是估算值；来源标为独立的 `kimi-config-window`，悬停文案说明取自配置。ACP 没有独立压缩方法，`compactSession()` 明确返回 `compaction-unsupported`，面板不显示「压缩上下文」；`/compact` 斜杠命令可用但只回纯文本完成提示、无机器完成事件，本轮不接线；`[loop_control].reserved_context_size` 只作用于 CLI 自身循环。用户向说明见 `docs/kimi-code-guide.md`，官方对照见 `.ch/docs/references/kimi-code-official-reference.md`，排障见 `.ch/docs/runbooks/kimi-code-config.md`。
- `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md`
- OpenCode coding / Loop 入口、one-shot 运行语义、模型职责及与 interactive runner 的边界，见上述事实来源与 `.ch/docs/design-docs/vscode-cli-extension-runtime.md`。
- P0 性能与内存硬化已完成：停止、扩展停用或 reload 会统一阻止新任务并尽力停止主进程、并行进程、交互运行和受管 OpenCode server；OpenCode raw stdout/stderr 与 JSONL 未完成行有明确上限且 activity 检测不再按 chunk 重扫完整历史；回放导出为 JSONL，按 tab 不限制记录条数和总字节，仍保留单条字节预算，overlay 关闭时不构建完整记录 DOM；Assistant delta 流式阶段轻量更新、idle/final 再完整 Markdown 渲染；附件上传在前端和 Extension Host 双端限制为最多 10 个文件、单文件 20 MiB、不限制总大小，并提供中文超限提示。
- Loop 开发级子任务高级 Skill 指导已下线；当前不再加载或注入内置 Workflow Skill，也不提供对应开关。历史说明以 `FEATURE_INVENTORY.md` 的 removed 条目和归档执行计划为准。
- 配置中心不再提供 MCP 管理，不会从配置页安装、覆盖或卸载 MCP，也不会改写用户磁盘上已有的 MCP 配置。内置 MCP 市场目录和 `npm run validate:mcp-marketplace` 已删除。
- Loop / Loop+ 模型选择按 CLI 能力统一：Claude 无插件侧模型下拉，Codex 普通 Coding 保持单模型；Codex 切到 Loop 或 Loop+ 时显示主模型/子模型两个选择器，并分别显示主任务/子任务思考力度；OpenCode 同样显示主模型/子模型两个角色，底层 `model` / `small_model` 仅作为 OpenCode CLI 配置字段适配。Loop 主任务、主持/复核和续跑使用主模型及主任务思考力度，Loop 子任务使用子模型及子任务思考力度。缺少子模型时兼容回退并在运行记录中保留原因。Loop 和 Loop+ completed 后，主任务对话都会追加独立的最终完成总结气泡；Loop/Loop+ 使用主任务回答结论与整体任务总结。Loop+ 的完成状态先成功落盘再写入主任务消息。Loop 子任务、辩论参与者和主持人成功结束后固定自动关闭子 tab，不再提供关闭开关；群聊“继续执行”和主任务 Tab 中断后继续输入都使用主任务 Tab 当前 CLI 分组、当前激活配置和当前模型，跨 CLI 时保留同一任务 ID 并迁移任务 Store 归属；`needs-review`、`error`、`stopped` 中断终态不再被旧编排所有权显示为执行中。内部思考 wrapper 定向清洗且不影响普通 HTML 标签。

Harness 骨架 / 长期记忆开关口径见 `docs/LONG_TERM_MEMORY_DESIGN.md`：该工作区开关默认关闭；若当前工作区已存在 `.ch` 目录，则开关展示为已勾选且禁用。开启时先弹窗确认；确认后才安装 `.ch/`、`.agents/`、`ARCHITECTURE.md`、根级 `AGENTS.md` 模板、只引用 `AGENTS.md` 的 `CLAUDE.md`，并创建或补充根级 `.gitignore` 以忽略 `.codegraph/`；骨架初始化不会自动安装 CodeGraph、注册 MCP 或初始化索引。工作区页另有独立 CodeGraph 开关，当前工作区存在 `.codegraph/` 索引目录时直接显示已勾选且禁用；没有索引时点击后才按当前状态补齐：未安装 CLI 时执行完整安装、MCP 注册和初始化；CLI 已安装但 MCP 未注册时跳过 npm；CLI 与 MCP 已就绪时只执行 `codegraph init`。尚未安装时，对话或 Loop 主任务运行态不会禁用这两个复选框。安装完成监测仍要求 CLI、MCP 交互和工作区索引全部就绪，兼容 Windows 和 macOS。初始化收尾阶段会再确认是否让当前 AI 对话以 Vibe 模式初始化 `ARCHITECTURE.md`，确认后复用当前 CLI 分组、配置和模型发起架构分析任务。长期记忆热区写入 `.ch/docs/memory/`，自动写入只进入 `EVENT_MEMORY.md` 的可复用事件，不自动写 `ROLLING_SUMMARY.md`，generated recall 写入运行态 `~/.sinitek_cli/memory-generated/<workspace>/memory-index/`，插件侧踩坑记录写入 `.ch/docs/runbooks/PITFALLS.md`；不控制 Codex / Claude / OpenCode 外部 CLI 自带记忆、历史或配置。

Claude 配置补充口径：配置卡片支持可视化与 JSON 两种模式，点击配置档案默认进入 JSON 源码模式，管理用户级 `~/.claude/settings.json`。可视化覆盖默认/回退/可选模型、推理强度、常用行为、权限规则、API/网关字段，并可独立设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL`；未展示字段和额外环境变量保持不变，无效 JSON 不覆盖有效可视化状态。 Claude / OpenCode / Codex 三组可视化参数 label 右侧都有问号 tooltip，枚举参数会提示可选值；“查看范例”统一放在配置文件名右侧并对齐 OpenCode 交互风格。

配置入口补充口径：从 AI 对话面板点击“配置”会立即打开并前台聚焦 VS Code 编辑器主区域内的 `WebviewPanel`，不进入 Zen Mode。活动栏、状态栏、标题栏和底部面板保持显示，同时隐藏主侧栏和辅助侧栏并把当前编辑器组拉到最大宽度，使配置页尽量占满可用宽度；重复点击复用同一面板并再次拉满宽度，关闭后恢复本次加宽隐藏的侧栏和编辑器组尺寸。VS Code 扩展公开 API 不支持任意 Webview 的原生模态弹窗，加宽命令不可用时保持普通编辑器面板，不启动独立浏览器或本地 HTTP 页面。配置页自身铺满 WebviewPanel 剩余视口，大型配置浮层使用近满屏宽高以减少左右和底部空白；配置页交互保持携宁 CLI 配置页能力，视觉颜色和字体使用 VS Code 主题语义变量；完整事实以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 为准。

Codex 配置补充口径：配置中心管理 `~/.codex/config.toml` 和既有 `~/.codex/auth.json` 入口。`config.toml` 是 Codex 主配置文件，格式为 TOML，不是 JSON；页面保留常用字段可视化编辑与 TOML 源码编辑，点击配置档案默认进入 TOML 源码模式；Provider 可视化不提供 `env_key` 输入。插件不展示、读取、写入、备份或导入导出 `~/.codex/.env`，也不删除用户已有文件。若配置页空白，应优先排查本插件 Webview 渲染和配置解析；`AugmentExtensionSidecar` 403 通常是 Augment 扩展侧请求失败，不能直接作为本插件配置页空白根因。完整事实以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 和 `.ch/docs/references/cli-runtime-reference.md` 为准。
OpenCode 相关补充口径：OpenCode 官方 TUI commands 文档支持 `/compact`（alias `/summarize`）来 compact current session，配置文档支持 `compaction.auto` 默认自动压缩，并提供 `OPENCODE_DISABLE_AUTOCOMPACT` 环境变量关闭自动压缩；插件侧可纳入手动压缩按钮和执行后自动压缩，但非交互模式是否能可靠附着既有会话以 runtime/UI 子任务验证为准。OpenCode 在插件里有两个明确配置文件：模型/Provider 配置中心维护 `~/.opencode/config.json`，配置中心不再用 MCP 市场维护官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp`；不再展示、要求、生成或保存 `~/.opencode/.env`。模型配置范例 provider 名称统一使用 `myAPI`，并展示顶层 `model` / `small_model` 和两个模型定义，不再示例化思考力度 `options` / `variants`，也不再内嵌 MCP 示例以免混淆。OpenCode 模式的主模型/子模型下拉只从 active config 的 `provider.<id>.models` 加载且没有管理入口；下拉仅显示模型 `name`（缺失时回退 model id），不显示可见 label、思考力度说明或“跟随配置”选项。配置卡片提供 Provider 列表 + 模型列表的可视化编辑器，可从默认 JSON 源码模式切换可视化；所有单值下拉（含 Claude、OpenCode、Codex）统一为与主模型 `model` 一致的可搜索、可清除 Ant Design `Select`；配置档案「复制配置」只在当前 CLI 内创建副本，确认框输入可修改的新名称，不再选择目标 CLI；Provider `npm` 会展示 OpenCode 官方 24 个 bundled loader 建议，并保留任意自定义 npm 包输入。支持 Provider/模型常用字段、主/子角色、重命名引用同步、悬空引用校验和未知字段保留；可视化不再配置思考力度，已有 variants 仅原样保留。普通和并行对话任务使用主模型；Loop 主任务、主持/复核和续跑使用主模型，Loop 子任务使用子模型。思考力度下拉与 Codex 相同，不依赖配置，选中值由 `--variant` 传递；子模型没有 `--small-model` 参数并通过 runtime config overlay 的 `small_model` 兼容字段调整，其内部 `small: true` 请求忽略 variants、实际使用 options，因此 overlay 会写入所选 reasoningEffort。配置中心不再从 Claude / Codex 生成 OpenCode 配置。
