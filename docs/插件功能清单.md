# 插件功能清单

本文档是兼容入口。当前功能清单的事实来源请阅读：

- `.ch/docs/product-specs/FEATURE_INVENTORY.md`
- `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md`
- OpenCode coding / Loop 入口、one-shot 运行语义、模型职责及与 interactive runner 的边界，见上述事实来源与 `.ch/docs/design-docs/vscode-cli-extension-runtime.md`。
- Loop 开发级子任务可使用内置高级 Skill 指导；仅 development 启用，普通主从与红蓝模式均覆盖，非开发及校验失败继续原 Loop 直接安排。完整选择、宿主校验、快照重试、安全降级和首版限制见上述能力规格的“3.3.1 Loop 开发级子任务高级 Skill 指导”及 `FEATURE_INVENTORY.md` 对应条目。
- OpenCode 全局 MCP 通过官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp` 直接安装、覆盖和卸载，CLI 仅用于列表与健康检测；内置 MCP 市场目录已刷新为官方/权威候选，并由 `npm run validate:mcp-marketplace` 校验中文描述、官方来源和旧来源黑名单。
- Loop 模型选择按 CLI 能力统一：Claude 无插件侧模型下拉，Codex 只选一个模型并供全部 Loop 角色复用，OpenCode 继续保留自身大模型/小模型；群聊“继续执行”和主任务 Tab 中断后继续输入都使用主任务 Tab 当前 CLI 分组、当前激活配置和当前模型，跨 CLI 时保留同一任务 ID 并迁移任务 Store 归属；`needs-review`、`error`、`stopped` 中断终态不再被旧编排所有权显示为执行中。内部思考 wrapper 定向清洗且不影响普通 HTML 标签。

Harness 骨架 / 长期记忆开关口径见 `docs/LONG_TERM_MEMORY_DESIGN.md`：该工作区开关默认关闭，开启时先弹窗确认；确认后才安装 `.ch/`、`.agents/`、`ARCHITECTURE.md`、根级 `AGENTS.md` 模板、只引用 `AGENTS.md` 的 `CLAUDE.md`，并创建或补充根级 `.gitignore` 以忽略 `.codegraph/`，随后在终端启动 CodeGraph 设置。初始化收尾阶段会再确认是否让当前 AI 对话以 Vibe 模式初始化 `ARCHITECTURE.md`，确认后复用当前 CLI 分组、配置和模型发起架构分析任务。长期记忆热区写入 `.ch/docs/memory/`，插件侧踩坑记录写入 `.ch/docs/runbooks/PITFALLS.md`；不控制 Codex / Claude / OpenCode 外部 CLI 自带记忆、历史或配置。

Claude 配置补充口径：配置卡片支持可视化与 JSON 两种模式，管理用户级 `~/.claude/settings.json`。可视化覆盖默认/回退/可选模型、推理强度、常用行为、权限规则、API/网关字段，并可独立设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL`；未展示字段和额外环境变量保持不变，无效 JSON 不覆盖有效可视化状态。 Claude / OpenCode / Codex 三组可视化参数 label 右侧都有问号 tooltip，枚举参数会提示可选值；“查看范例”统一放在配置文件名右侧并对齐 OpenCode 交互风格。

Codex 配置补充口径：配置中心管理 `~/.codex/config.toml` 和 `~/.codex/.env`。`config.toml` 是 Codex 主配置文件，格式为 TOML，不是 JSON；页面支持常用字段可视化编辑与 TOML 源码编辑，`.env` 按独立环境变量文件管理。若配置页空白，应优先排查本插件 Webview 渲染和配置解析；`AugmentExtensionSidecar` 403 通常是 Augment 扩展侧请求失败，不能直接作为本插件配置页空白根因。完整事实以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 和 `.ch/docs/references/cli-runtime-reference.md` 为准。

OpenCode 相关补充口径：OpenCode 官方 TUI commands 文档支持 `/compact`（alias `/summarize`）来 compact current session，配置文档支持 `compaction.auto` 默认自动压缩，并提供 `OPENCODE_DISABLE_AUTOCOMPACT` 环境变量关闭自动压缩；插件侧可纳入手动压缩按钮和执行后自动压缩，但非交互模式是否能可靠附着既有会话以 runtime/UI 子任务验证为准。OpenCode 在插件里有两个明确配置文件：模型/Provider 配置中心维护 `~/.opencode/config.json`，全局 MCP 市场安装/卸载维护官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp`；不再展示、要求、生成或保存 `~/.opencode/.env`。模型配置范例 provider 名称统一使用 `myAPI`，并展示顶层 `model` / `small_model`、两个模型定义、主模型默认 `options` 与运行时 `variants`、小模型固定 `options` 与可选 `variants`，不再内嵌 MCP 示例以免混淆。OpenCode 模式的两个模型下拉只从 active config 的 `provider.<id>.models` 加载且没有管理入口；下拉仅显示模型 `name`（缺失时回退 model id），不显示可见 label、思考力度说明或“跟随配置”选项。配置卡片默认提供 Provider 列表 + 模型列表的可视化编辑器，可切换 JSON 高级模式；支持 Provider/模型常用字段、主/小角色、逗号思考力度、重命名引用同步、悬空引用校验和未知字段保留。普通、并行和 Loop 对话任务仍使用主模型，小模型只用于 OpenCode 内部轻量请求。主模型 variant 由 `--variant` 选择，小模型没有 `--small-model` 参数并通过 runtime config overlay 调整，其内部请求忽略 variants、实际使用 options。配置中心不再从 Claude / Codex 生成 OpenCode 配置。
