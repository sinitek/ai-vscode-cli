# 插件功能清单

本文档是兼容入口。当前功能清单的事实来源请阅读：

- `.ch/docs/product-specs/FEATURE_INVENTORY.md`
- `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md`
- OpenCode coding / Loop 入口、one-shot 运行语义、模型职责及与 interactive runner 的边界，见上述事实来源与 `.ch/docs/design-docs/vscode-cli-extension-runtime.md`。
- OpenCode 全局 MCP 通过官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp` 直接安装、覆盖和卸载，CLI 仅用于列表与健康检测。

Harness 骨架 / 长期记忆开关口径见 `docs/LONG_TERM_MEMORY_DESIGN.md`：该工作区开关默认关闭，开启时先弹窗确认；确认后才安装 `.ch/`、`.agents/`、`ARCHITECTURE.md`、根级 `AGENTS.md` 模板、只引用 `AGENTS.md` 的 `CLAUDE.md`，并创建或补充根级 `.gitignore` 以忽略 `.codegraph/`，随后在终端启动 CodeGraph 设置。初始化收尾阶段会再确认是否让当前 AI 对话以 Vibe 模式初始化 `ARCHITECTURE.md`，确认后复用当前 CLI 分组、配置和模型发起架构分析任务。长期记忆热区写入 `.ch/docs/memory/`，插件侧踩坑记录写入 `.ch/docs/runbooks/PITFALLS.md`；不控制 Codex / Claude / OpenCode 外部 CLI 自带记忆、历史或配置。

Claude 配置补充口径：配置卡片支持可视化与 JSON 两种模式，管理用户级 `~/.claude/settings.json`。可视化覆盖默认/回退/可选模型、推理强度、常用行为、权限规则、API/网关字段，并可独立设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL`；未展示字段和额外环境变量保持不变，无效 JSON 不覆盖有效可视化状态。

OpenCode 相关补充口径：配置中心示例已按 OpenCode `config.json` / 自定义 provider schema 更新；配置中心只维护一个 `~/.opencode/config.json`，不再展示、要求、生成或保存 `~/.opencode/.env`。范例 provider 名称统一使用 `myAPI`，并展示顶层 `model` / `small_model`、两个模型定义、主模型默认 `options` 与运行时 `variants`、小模型固定 `options` 与可选 `variants`。OpenCode 模式的两个模型下拉只从 active config 的 `provider.<id>.models` 加载且没有管理入口；下拉仅显示模型 `name`（缺失时回退 model id），不显示可见 label、思考力度说明或“跟随配置”选项。配置卡片默认提供 Provider 列表 + 模型列表的可视化编辑器，可切换 JSON 高级模式；支持 Provider/模型常用字段、主/小角色、逗号思考力度、重命名引用同步、悬空引用校验和未知字段保留。普通、并行和 Loop 对话任务仍使用主模型，小模型只用于 OpenCode 内部轻量请求。主模型 variant 由 `--variant` 选择，小模型没有 `--small-model` 参数并通过 runtime config overlay 调整，其内部请求忽略 variants、实际使用 options。配置中心不再从 Claude / Codex 生成 OpenCode 配置。
