# 插件功能清单

本文档是兼容入口。当前功能清单的事实来源请阅读：

- `.ch/docs/product-specs/FEATURE_INVENTORY.md`
- `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md`
- Graph 模式已提供 AI planner 先生成 realized DAG 的运行内核、真正可视 DAG 面板和 Phase 2 恢复交互：主 Webview 可选择 Graph，后端先运行 `plan` AI planner 节点并按其 `plannedGraph` materialize 真实 DAG；Graph tab 显示 `🗺️` 标识，历史会话列表会以 Graph badge 标记 Graph 会话，active Graph tab 的底部运行状态行固定提供“打开 Graph 图”按钮且后续普通回复不会清除该入口；普通“打开 Graph 运行图”入口只由主 Graph tab / 图级消息按同一 run 输出一次，节点/子任务会话不重复展示；节点 tab 在节点 runner 结束后自动关闭。面板用对齐目标工作流画布的 `@dagrejs/dagre` full-canvas left-to-right 自动布局展示运行图，参数按当前节点尺寸调优，并支持布局后碰撞消解、长标题/多下游节点动态高度、dagre 失败时拓扑层级兜底；用 SVG 边/箭头/非依赖流程边短目的标签和矩形类型卡片展示运行图，不再保留下方常驻节点详情分栏；可见线条只包含 `depends_on`、`if_pass`、`if_fail`、`review_feedback`、`human_approved` 等流程边，`evidence_for` / `conflicts_with` 不进入画布连线；依赖边不显示可见文字，非依赖流程边的短标签保持单行且不随反向路径镜像翻转，完整说明保留在 title / aria / list；已经过边按类型着色：`depends_on` 保持 VS Code 主题蓝色，`if_pass` 绿色、`if_fail` 红色、`review_feedback` 黄色、`human_approved` 橙色，未经过边保持原样；节点卡片按 `node.kind` 使用 VS Code 主题变量映射不同 tone，显示 type badge、短标识、状态和 Start/Decision/End/Step 语义 chip；节点表面显示 12 个连接点，边按两节点相对位置自动选择端口，视觉层每个方向只渲染一条代表边，正反向边使用不同连接点避免重合；用户可拖拽节点微调当前 run 的可视位置，也可在背景按住鼠标左键拖动画布平移；节点拖拽按 zoom 比例换算，边 path/端口属性/标签坐标/画布同步重算，拖拽移动不会误触发详情，节点位置和 zoom 按 `graphRunId` 本地持久化；右上角缩放下拉固定 25%、50%、75%、100%、125%，默认 75%，Reset 仅为紧凑控件而不是占空间长文案且不重置 zoom。单击节点打开详情弹窗，详情弹窗展示控制入口和 Evidence/证据区。review 节点 prompt 会从上游节点 `writeFiles`、communication file 和 artifactRef 生成评审范围，要求按候选改动文件过滤 git status/diff，范围外 dirty workspace 改动不单独导致 failed。Graph UI 不再常驻展示 Stop 能力边界说明；具体 Stop 操作结果或错误仍通过运行消息/状态反馈表达。本地 run store / `graph.json` / `events.jsonl` 仍是事实来源；Graph 节点默认在项目工作区 direct 执行，不再为新 run 创建 Graph worktree、checkpoint 或 merge-back。当前支持 Continue/Resume、“我要说话”、Retry、历史 worktree run 的 Feedback rollback 回退上游返工、Stop、sleeping run auto wake、有限结构化条件边、blocked 归一 failed、返工记录和节点证据区；完整能力、文件落点和限制见上述事实来源及 `.ch/docs/design-docs/graph-orchestration-mode.md`。仍不提供图编辑器、模板库、DAG 结构编辑、完整人工审批工作流、局部返工路径编辑、复杂布尔条件编辑器、任意条件重写/可视化重规划、rollback 预演或证据文件正文读取；背景平移、12-port、非依赖流程边短标签、语义 chip 和类型着色矩形卡片仅为视觉层优化，不改变 DAG 结构或调度语义；Stop 只保证 Graph 状态落盘，并且仅在存在 active CLI run graph 映射时尝试停止真实进程，不能确认外部进程已退出。
- Graph direct run 已支持基于结构化失败分类的自动返工：failed test/review/merge/summary 节点若推荐 `direct_rework` 且存在 active `review_feedback` / `if_fail` 显式返工边，宿主会重置声明 scope、返工目标和失败源节点后继续调度；direct 仍不做 git rollback/checkpoint。新增 `npm run validate:whitespace` 用于检查 tracked 和 untracked 文件行尾空白，补齐 `git diff --check` 对新文件的盲区。
- Graph 动态扩图续跑已接入当前 run：审核失败、验证失败、merge/summary 失败、blocked 或无可运行节点时，宿主会先尝试既有 `direct_rework`；普通成功推进 tick 不会追加 `replan-*`；当直接返工不可用或需要新增返工范围时，会追加最多 3 个主模型 `replan-*` 节点，让主模型在当前图内输出 `plannedGraph` 增量继续执行。增量物化只允许新增节点/边，不覆盖旧节点、不让新增边指向已有节点；旧 failed/blocked 节点通过 `if_fail` 或 `evidence_for` 作为触发和证据，新增根节点自动依赖当前 replanner，并由新的续跑 summary 收束。
- Graph planner 现在默认要求 AI 自主设计图时尽量并行：可拆分且互不冲突的实现、测试、文档或组件任务应从 `plan` fan-out 并行展开，并通过 test/review/merge/summary fan-in 收束；planner 漏填 `plannedGraph.maxConcurrent` 时，宿主会按首批无冲突根节点推断并发上限，运行时只由显式 `conflictGroup` 或重叠 `writeFiles` 串行化；未声明 `writeFiles` 的 ready 节点可并行执行但必须被规划约束视为不写文件。
- Graph 支持 advisory 验证节点：完整单测、全仓测试、全量 lint 等覆盖面大且可能包含历史/范围外失败的验证节点可声明 `blocking:false`，失败后仍进入 review/summary 的证据和未解决事项，但不会单独阻断结构依赖继续执行；相关 focused 验证仍应作为硬性关卡。
- Graph planner 也会在重构/迁移时要求独立测试契约适配节点和测试 `writeFiles`；运行态会把旧 source-contract / missing write scope 等失败写入 `GraphNodeRecord.failure` 与 `node.failed` 事件，并在 needs-review / idle 文案展示 category、confidence、signals、recommendedRecovery、recommendedWriteFiles 和 nodeDraft。最近 `test-schema-definitions` 失败属于 `missing_write_scope`，signals 包含 `stale_test_contract`，不应被当作单纯 SQL 实现重试。
- GraphRunPanel 自动布局已按目标系统 workflow 画布经验升级：默认 LR，内部支持 `LR` / `RL` / `TB` / `BT`，并支持调优参数、多根 fallback、`review_feedback` / 上游 `if_fail` non-ranking 回边、方向感知 collision、端口分离，以及 selected/running/sleeping/blocked/failed 初始居中；工具栏可手动定位当前 `running` 节点到可见画布中间；这些仅优化当前运行图可视表达，不改变 DAG 结构或调度语义。
- OpenCode coding / Loop 入口、one-shot 运行语义、模型职责及与 interactive runner 的边界，见上述事实来源与 `.ch/docs/design-docs/vscode-cli-extension-runtime.md`。
- P0 性能与内存硬化已完成：停止、扩展停用或 reload 会统一阻止新任务并尽力停止主进程、并行进程、交互运行和受管 OpenCode server；OpenCode raw stdout/stderr 与 JSONL 未完成行有明确上限且 activity 检测不再按 chunk 重扫完整历史；Run Stream 有记录数、单条字节和总字节预算，overlay 关闭时不构建完整记录 DOM；Assistant delta 流式阶段轻量更新、idle/final 再完整 Markdown 渲染；附件上传在前端和 Extension Host 双端限制为最多 10 个文件、单文件 20 MiB、不限制总大小，并提供中英文超限提示。
- Loop 开发级子任务高级 Skill 指导已下线；当前不再加载或注入内置 Workflow Skill，也不提供对应开关。历史说明以 `FEATURE_INVENTORY.md` 的 removed 条目和归档执行计划为准。
- OpenCode 全局 MCP 通过官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp` 直接安装、覆盖和卸载，CLI 仅用于列表与健康检测；内置 MCP 市场目录已刷新为官方/权威候选，并由 `npm run validate:mcp-marketplace` 校验中文描述、官方来源和旧来源黑名单。
- Loop / Graph 模型选择按 CLI 能力统一：Claude 无插件侧模型下拉，Codex 普通 Coding 保持单模型；Codex 切到 Loop 或 Graph 时显示主模型/子模型两个选择器，并分别显示主任务/子任务思考力度；OpenCode 同样显示主模型/子模型两个角色，底层 `model` / `small_model` 仅作为 OpenCode CLI 配置字段适配。Loop 主任务、主持/复核和续跑使用主模型及主任务思考力度，Loop 子任务使用子模型及子任务思考力度；Graph planner 和最终 `summary` 节点使用主模型及主任务思考力度，Graph 其他执行节点使用子模型及子任务思考力度；缺少子模型时兼容回退并在运行记录中保留原因。Graph completed 后主 Graph tab 会追加主模型 summary 节点产出的最终总结气泡；Loop 子任务、辩论参与者和主持人成功结束后固定自动关闭子 tab，不再提供关闭开关；群聊“继续执行”和主任务 Tab 中断后继续输入都使用主任务 Tab 当前 CLI 分组、当前激活配置和当前模型，跨 CLI 时保留同一任务 ID 并迁移任务 Store 归属；`needs-review`、`error`、`stopped` 中断终态不再被旧编排所有权显示为执行中。内部思考 wrapper 定向清洗且不影响普通 HTML 标签。

Harness 骨架 / 长期记忆开关口径见 `docs/LONG_TERM_MEMORY_DESIGN.md`：该工作区开关默认关闭，开启时先弹窗确认；确认后才安装 `.ch/`、`.agents/`、`ARCHITECTURE.md`、根级 `AGENTS.md` 模板、只引用 `AGENTS.md` 的 `CLAUDE.md`，并创建或补充根级 `.gitignore` 以忽略 `.codegraph/`，随后在终端启动最新版 CodeGraph 安装、Codex MCP 注册和当前工作区索引初始化。工作区页另有“安装 CodeGraph”按钮，可独立安装/升级本机 CodeGraph CLI 到最新版本，兼容 Windows 和 macOS。初始化收尾阶段会再确认是否让当前 AI 对话以 Vibe 模式初始化 `ARCHITECTURE.md`，确认后复用当前 CLI 分组、配置和模型发起架构分析任务。长期记忆热区写入 `.ch/docs/memory/`，generated recall 写入运行态 `~/.sinitek_cli/memory-generated/<workspace>/memory-index/`，插件侧踩坑记录写入 `.ch/docs/runbooks/PITFALLS.md`；不控制 Codex / Claude / OpenCode 外部 CLI 自带记忆、历史或配置。

Claude 配置补充口径：配置卡片支持可视化与 JSON 两种模式，点击配置档案默认进入 JSON 源码模式，管理用户级 `~/.claude/settings.json`。可视化覆盖默认/回退/可选模型、推理强度、常用行为、权限规则、API/网关字段，并可独立设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL`；未展示字段和额外环境变量保持不变，无效 JSON 不覆盖有效可视化状态。 Claude / OpenCode / Codex 三组可视化参数 label 右侧都有问号 tooltip，枚举参数会提示可选值；“查看范例”统一放在配置文件名右侧并对齐 OpenCode 交互风格。

配置入口补充口径：从 AI 对话面板点击“配置”会立即打开并前台聚焦 VS Code 编辑器主区域内的 `WebviewPanel`，随后尝试进入 VS Code Zen Mode，隐藏工作台外围以接近全屏弹窗；重复点击复用同一面板，关闭后恢复由本插件进入的 Zen Mode。VS Code 扩展公开 API 不支持任意 Webview 的原生模态弹窗，Zen Mode 不可用时回退为普通编辑器面板，不启动独立浏览器或本地 HTTP 页面。配置页自身铺满 WebviewPanel 剩余视口，大型配置浮层使用近满屏宽高以减少左右和底部空白；配置页交互保持携宁 CLI 配置页能力，视觉颜色和字体使用 VS Code 主题语义变量；完整事实以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 为准。

Codex 配置补充口径：配置中心管理 `~/.codex/config.toml` 和既有 `~/.codex/auth.json` 入口。`config.toml` 是 Codex 主配置文件，格式为 TOML，不是 JSON；页面保留常用字段可视化编辑与 TOML 源码编辑，点击配置档案默认进入 TOML 源码模式；Provider 可视化不提供 `env_key` 输入。插件不展示、读取、写入、备份或导入导出 `~/.codex/.env`，也不删除用户已有文件。若配置页空白，应优先排查本插件 Webview 渲染和配置解析；`AugmentExtensionSidecar` 403 通常是 Augment 扩展侧请求失败，不能直接作为本插件配置页空白根因。完整事实以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 和 `.ch/docs/references/cli-runtime-reference.md` 为准。

OpenCode 相关补充口径：OpenCode 官方 TUI commands 文档支持 `/compact`（alias `/summarize`）来 compact current session，配置文档支持 `compaction.auto` 默认自动压缩，并提供 `OPENCODE_DISABLE_AUTOCOMPACT` 环境变量关闭自动压缩；插件侧可纳入手动压缩按钮和执行后自动压缩，但非交互模式是否能可靠附着既有会话以 runtime/UI 子任务验证为准。OpenCode 在插件里有两个明确配置文件：模型/Provider 配置中心维护 `~/.opencode/config.json`，全局 MCP 市场安装/卸载维护官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp`；不再展示、要求、生成或保存 `~/.opencode/.env`。模型配置范例 provider 名称统一使用 `myAPI`，并展示顶层 `model` / `small_model`、两个模型定义、主模型默认 `options` 与运行时 `variants`、子模型固定 `options` 与可选 `variants`，不再内嵌 MCP 示例以免混淆。OpenCode 模式的主模型/子模型下拉只从 active config 的 `provider.<id>.models` 加载且没有管理入口；下拉仅显示模型 `name`（缺失时回退 model id），不显示可见 label、思考力度说明或“跟随配置”选项。配置卡片提供 Provider 列表 + 模型列表的可视化编辑器，可从默认 JSON 源码模式切换可视化；支持 Provider/模型常用字段、主/子角色、逗号思考力度、重命名引用同步、悬空引用校验和未知字段保留。普通和并行对话任务使用主模型；Loop 主任务、主持/复核和续跑使用主模型，Loop 子任务使用子模型；Graph planner 和最终 `summary` 节点使用主模型，Graph 其他执行节点使用子模型。主模型 variant 由 `--variant` 选择，子模型没有 `--small-model` 参数并通过 runtime config overlay 的 `small_model` 兼容字段调整，其内部 `small: true` 请求忽略 variants、实际使用 options。配置中心不再从 Claude / Codex 生成 OpenCode 配置。
