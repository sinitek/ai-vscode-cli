DeepSeek Harness 已作为 `dsh` 接入。命令顺序是 `codex`、`claude`、`opencode`、`grok`、`dsh`。交互主路径是 `dsh --profile acp`。配置只接受明确的 `--patch`，不能覆盖 `--profile`，也不能切换 headless、sdk 或 tui。默认范例模型 id 为 `deepseek-v4.1-flash`，不带 `subcoco/`；模型 id 按服务端点原样配置，不自动增删前缀，运行时必须与 `models[].id`、`acpModel` 和 ACP 广告一致。凭据默认引用 `SINITEK_DSH_API_KEY`；也可在 profile 根级直接配置 `apiKey`，明文仅保存在本机私有配置和备份中，运行 patch 不包含密钥，直接配置优先于外部环境变量。配置页分组在 Grok 之后。配置页同时提供 JSON 文本和可视化两种模式，编辑同一份完整 JSON。已接受的额外顶层字段和模型对象字段会保留。未验证字段和嵌套密钥在验证阶段拒绝，且不写入运行 patch。provider 只读。可视化不展示 `apiKeyEnv`，缺失时保存和 patch 自动规范化为 `SINITEK_DSH_API_KEY`；`baseURL`、模型 id 和根级 `apiKey` 可编辑。可选公共字段 `displayName`、`timeoutMs`、`streamIdleTimeoutMs`、`retryPolicy` 不在可视化中展示或新范例中生成，已有 JSON 值保留。`models` 按已安装 schema 保持有序数组，可新增、编辑、删除并选择当前 `acpModel`。详情区不显示激活状态。Skills 市场目标共七个，顺序保持 Claude、OpenCode、Grok、Codex、DSH、Kimi Code、ZCode。Skills 根是 `<DSH_HOME>/skills`，规则链读取 DSH 的 `AGENTS.md`。未配置模型不能执行。usage 缺失不显示为 0。`usage_update.size` 的 adapter-fallback 窗口不能冒充服务容量。思考力度只按 profile 能力声明和 ACP 当前公布的标量处理，不从模型名称推断；默认验证模型提供 `low`、`high`、`xhigh`、`max`，面板隐藏 `off` 和空 value，其他自定义模型未声明能力时不显示选项。原生 compaction 明确不支持。真实权限请求和图形 Extension Host 点击验收未验证，不得写成已完成。字段边界见 `.ch/docs/references/dsh-custom-provider-contract.md`。

Kimi Code 已作为 `kimi-code` 接入，命令顺序为 `codex`、`claude`、`opencode`、`grok`、`dsh`、`kimi-code`，可执行命令默认 `kimi`，观测名称 `Kimi Code`。官方包 `@moonshot-ai/kimi-code`（bin `kimi`，要求 Node >= 22.19.0）。官方安装入口有两条：脚本 `curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`（Windows PowerShell `irm https://code.kimi.com/kimi-code/install.ps1 | iex`，官方推荐、无需预装 Node）与 npm `npm install -g @moonshot-ai/kimi-code`；插件自身的诊断修复与「安装命令」只用可回滚的 `npm install -g @moonshot-ai/kimi-code@latest`（本机实测 2.3.2），不执行管道脚本。版本检查 `kimi --version`，配置自检 `kimi doctor config [path]`，升级 `kimi upgrade` 或 npm 重装 `@latest`。配置是 `~/.kimi-code/config.toml`（TOML，snake_case，可用 `KIMI_CODE_HOME` 改目录），默认模型别名 `subcoco/kimi-k3.1-pro`，默认范例的 `base_url` 是团队本机网关 `http://127.0.0.1:33391/v1`（与 Grok/Claude 一致的本机转发约定，可改）。免审批真实存在，但官方 `--auto` / `--yolo` 与 `-p/--prompt` 互斥，插件一次性任务走 `-p`，因此免审批必须写在 `default_permission_mode = "auto"`（默认新范例即 `auto`），启动命令默认只发 `kimi`，不拼 `--auto`。ACP 侧没有独立压缩方法，插件 `compactSession()` 返回 `compaction-unsupported`，也不伪装成本地压缩；`/compact` 斜杠命令本身可用（作为 prompt 文本触发后台异步压缩，只回纯文本完成提示、无机器完成事件），本轮不接线成按钮；`[loop_control].reserved_context_size` 只作用于 CLI 自己的会话循环。思考力度是原生能力：ACP `thinking` 选项只广告模型表允许的值（`capabilities` 缺省或为空数组时不广告 `thinking`；env-only 通道只有 `off`/`on`；显式 `support_efforts` 时为该数组子集，`always_thinking` 时不广告 `off`），插件只下发广告值，不改写 `ultra`、不伪造档位；广告里没有就报错并保留服务端确认值。默认配置文本与配置页范例已写入 `capabilities = ["thinking", "tool_use"]` 与完整 `support_efforts`，配置中心可视化可编辑「能力声明」「可用思考档位」且留空不删除；Webview 消费宿主的 `kimiThinkingOptions` / `kimiModeUpdate`（按 `tabId` 隔离、过滤非法值、只有 `off`/`on` 时禁用下拉）。上下文窗口展示取 `usage_update.size`，即配置声明的 `max_context_size`，不是估算值；`interactiveTurnKimi.ts` 标独立的 `contextWindowSource: "kimi-config-window"`，悬停文案说明窗口取自配置，DSH 的 `adapter-fallback` 语义不变。主/子模型复用插件通用角色选择，候选只取当前配置声明的模型：子任务未单独选择时先回落到普通对话所选模型，再回落到 `default_model`；Loop 子任务用子模型，Graph planner 与 `summary` 用主模型；Kimi 自身 `config.toml` 没有子模型字段，分工完全由插件调度实现。provider 必须配置 `api_key` 或 `api_key_env`，否则运行时报 `provider <名称> has no credential configured`，插件不从 Codex `auth.json` 复制，也不从 shell 回退读取任意密钥变量。交互主路径是官方 ACP `kimi acp`（JSON-RPC 2.0 over stdio），`args.kimi-code` 只允许 `--region mainland-cn|global`，其余参数一律拒绝；只使用 `session/new`、`session/resume`、`session/prompt`、`session/set_config_option`、`session/cancel`、`session/close`，不发送 `session/load`、`session/fork`、`session/delete`。配置页分组追加在 DSH 之后，可视化沿用 Grok 双栏布局，覆盖 `default_model`、`default_permission_mode`、`thinking.effort`、`loop_control.reserved_context_size` 与所选模型的 `provider`/`model`/`display_name`/`max_context_size`/`default_effort`/`capabilities`/`support_efforts`、`providers` 的 `type`/`base_url`/`api_key`/`api_key_env`；别名是 `[models."<别名>"]` 表键，`model` 才是真实模型 ID。Skills 市场目标共七个，顺序为 Claude、OpenCode、Grok、Codex、DSH、Kimi Code、ZCode；Kimi Code 用户级技能根是 `<KIMI_CODE_HOME>/skills`，全局规则 `<KIMI_CODE_HOME>/AGENTS.md`。用户向说明见 `docs/kimi-code-guide.md`，官方对照与差异清单见 `.ch/docs/references/kimi-code-official-reference.md`，排障见 `.ch/docs/runbooks/kimi-code-config.md`；完整运行时口径以 `.ch/docs/references/cli-runtime-reference.md` 为准。

DSH 思考力度不从模型名称推断，面板选项直接显示当前 ACP 广告且属于契约的原始 value。默认验证模型提供 `low`、`high`、`xhigh`、`max` 四档；面板隐藏 `off` 和空 value。其他自定义模型需明确声明 `reasoningEfforts` 和 DeepSeek `compat`，否则选择器禁用；选择后在下一次 prompt 前通过 `configId: "reasoning_effort"` 和 raw `value` 经 ACP 确认，未公布的值不会发送。

Loop / Graph 模型语义：Claude 不接受插件侧模型选择；Codex 普通 Coding 仍使用单模型，切到 Loop 或 Graph 时显示主模型/子模型两个选择器；OpenCode 也统一显示主模型/子模型口径，底层 `model` / `small_model` 仅作为 OpenCode CLI 配置字段适配。Loop 主任务、主持/复核和续跑使用主模型，Loop 子任务使用子模型；Graph planner 和最终 `summary` 节点使用主模型，Graph 其他执行节点使用子模型；子模型缺失时按主模型/单模型兼容回退并记录原因。内部 `<thinking>` / `<think>` / `<analysis>` / `<reasoning>` wrapper 会被定向解析或去标签，普通 HTML 标签不受影响。

配置中心不再安装或卸载 OpenCode 全局 MCP，也不会改写用户已有的 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json`。

P0 性能与内存硬化运行口径：停止、扩展停用或 reload 会统一阻止新任务并尽力停止主进程、并行进程、交互运行和受管 OpenCode server。OpenCode one-shot / parallel / interactive raw stdout/stderr 只保留有界 tail，JSONL 未完成行限制为 64 KiB，activity 检测使用增量状态而不是每个 chunk 重扫完整历史。回放导出为 JSONL，按 tab 不限制记录条数和总字节，仍保留单条字节预算，overlay 关闭时不构建完整记录 DOM；Assistant delta 流式阶段轻量更新，idle/final 阶段再完整 Markdown 渲染。附件上传在 Webview 与 Extension Host 双端限制为最多 10 个文件、单文件 20 MiB、不限制总大小，并按语言展示超限拒绝提示。

配置中心不再提供 MCP 市场，内置市场目录和 `npm run validate:mcp-marketplace` 已删除。

工具设置“工作区”页中的 harness 骨架开关默认关闭。用户开启时会先弹窗确认；确认后才会安装当前工作区 `media/workspace-scaffold` 对应的 `.ch/`、`.agents/`、`ARCHITECTURE.md`、根级 `AGENTS.md` 创建或追加模板、只引用 `AGENTS.md` 的 `CLAUDE.md`，并创建或补充根级 `.gitignore` 以忽略 `.codegraph/`；骨架初始化不会自动安装 CodeGraph、注册 MCP 或初始化索引。该页还提供独立 CodeGraph 开关，交互与 harness 骨架相同：默认关闭，点击后弹窗确认并开始安装；尚未安装时，对话或 Loop 主任务运行态不会禁用这两个复选框；安装完成后根据检测脚本自动勾选且禁用。判定条件为本机 `codegraph` CLI 可用、Codex/Claude/OpenCode 任一 MCP 已注册，以及当前工作区存在 `.codegraph/` 索引。Windows 使用 `cmd.exe`，macOS 使用默认 shell。初始化收尾阶段会再弹窗询问是否让 AI 初始化 `ARCHITECTURE.md`；用户确认后，插件把当前 AI 对话切到 Vibe 模式，并复用当前选择的 CLI 分组、配置和模型发起项目架构分析任务。该开关同时控制插件侧长期记忆召回/写入：热区写入 `.ch/docs/memory/`，generated recall 写入运行态 `~/.sinitek_cli/memory-generated/<workspace>/memory-index/`，踩坑记录写入 `.ch/docs/runbooks/PITFALLS.md`。不控制 Codex / Claude / OpenCode 外部 CLI 自带记忆、历史、压缩或配置。

工具设置“AI任务配置”页中的“人工交互”开关默认开启，保存为 `~/.sinitek_cli/settings.json` 的 `humanInteractionEnabled`。开启后，Codex Vibe/coding 交互任务会把 Codex app-server 的结构化人工澄清请求展示为 Webview 表单；Codex、Claude 和 OpenCode Vibe/coding 任务在用户明确要求 AI 先询问需求/细节但模型只返回普通问题列表时，也会兜底转为同一人工交互表单，并把问题里的“可选 / 选项 / 例如 / 如”候选项以及紧随问题的 `A.` / `B.` / `C.` 字母选项列表渲染成 radio/checkbox。提交后当前任务继续，拒绝或关闭表单会终止当前任务。完整运行时边界以 `.ch/docs/design-docs/vscode-cli-extension-runtime.md` 为准。

Claude 配置中心管理 `~/.claude/settings.json`，支持可视化与 JSON 高级模式，点击配置档案默认进入 JSON 源码模式。可视化覆盖官方常用核心字段，并可分别设置 `ANTHROPIC_DEFAULT_HAIKU_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_OPUS_MODEL`；未展示字段、额外 `env`、hooks 和权限扩展会保留，非法 JSON 不覆盖有效可视化状态。Claude / OpenCode / Codex 三组可视化参数 label 右侧都有问号 tooltip，枚举参数提示可选值；三组“查看范例”统一放在配置文件名右侧。完整口径以 `.ch/docs/references/cli-runtime-reference.md` 为准。

配置入口：从 AI 对话面板点击“配置”会立即打开并前台聚焦 VS Code 编辑器主区域内的 `WebviewPanel`，不进入 Zen Mode。活动栏、状态栏、标题栏和底部面板保持显示，同时隐藏主侧栏和辅助侧栏并把当前编辑器组拉到最大宽度，使配置页尽量占满可用宽度；重复点击复用同一面板并再次拉满宽度，关闭后恢复本次加宽隐藏的侧栏和编辑器组尺寸。VS Code 扩展公开 API 不支持任意 Webview 的原生模态弹窗，加宽命令不可用时保持普通编辑器面板；配置中心自身会铺满 WebviewPanel 剩余视口，大型配置浮层使用近满屏宽高以减少左右和底部空白；不启动独立浏览器或本地 HTTP 页面，视觉颜色和字体使用 VS Code 主题语义变量。完整产品口径以 `.ch/docs/product-specs/sinitek-cli-plugin-capabilities.md` 为准。

Codex 配置中心管理 `~/.codex/config.toml` 与既有 `~/.codex/auth.json` 入口。`config.toml` 是 Codex 主配置文件，格式为 TOML，不是 JSON；配置卡片保留可视化编辑和 TOML 源码编辑，点击配置档案默认进入 TOML 源码模式；Provider 可视化不提供 `env_key` 输入。插件不展示、读取、写入、备份或导入导出 `~/.codex/.env`，也不删除用户已有文件。配置页空白优先排查本插件 Webview 渲染和配置解析；`AugmentExtensionSidecar` 403 通常属于 Augment 扩展侧请求失败，不直接说明本插件配置页故障。完整口径以 `.ch/docs/references/cli-runtime-reference.md` 为准。

OpenCode 当前运行事实补充：OpenCode 官方 TUI commands 文档支持 `/compact`（alias `/summarize`）来 compact current session，配置文档支持 `compaction.auto` 默认自动压缩，并提供 `OPENCODE_DISABLE_AUTOCOMPACT` 环境变量关闭自动压缩；插件侧可纳入手动压缩按钮和执行后自动压缩，但非交互模式是否能可靠附着既有会话以 runtime/UI 子任务验证为准。OpenCode 在插件里明确分成两个配置文件：模型/Provider 配置中心维护 `~/.opencode/config.json`，配置中心不再用 MCP 市场维护官方 `${XDG_CONFIG_HOME:-~/.config}/opencode/opencode.json` 顶层 `mcp`；模型配置卡片点击配置档案默认进入 JSON 源码模式，且不再要求、生成或保存 `~/.opencode/.env`。模型配置示例使用可解析的 `myAPI` 双模型严格 JSON，包含主模型默认 `options` / 可切换 `variants` 和子模型固定 `options` / 可选 `variants`，不再内嵌 MCP 示例以免混淆。OpenCode 模式显示主模型与子模型两个下拉，候选只从 active config 的 `provider.<id>.models` 加载且不提供管理入口；底层顶层 `model` 对应主模型，`small_model` 作为 OpenCode CLI 兼容字段对应子模型。普通 one-shot / 并行对话使用主模型；Loop 主任务、主持/复核和续跑使用主模型，Loop 子任务使用子模型；Graph planner 与最终 `summary` 节点使用主模型，Graph 其他执行节点使用子模型。主模型通过 `--model provider/model` 和可选 `--variant` 运行；CLI 没有 `--small-model`，插件通过 runtime config overlay 覆盖顶层 `small_model`，且 OpenCode 内部 `small: true` 请求忽略 variants、实际使用该角色模型自身 options。所有 OpenCode 任务默认加入官方 `--auto`，自动批准未被显式拒绝的权限请求并支持默认外部目录访问；显式 `deny` 仍优先，插件不会强制覆盖用户权限策略。`@ai-sdk/openai-compatible` 只代表 API 协议适配器，不决定推理档位。one-shot / 并行任务通过 `opencode run --auto --format json --print-logs [message..]` 启动并解析 assistant 文本事件生成最终结论气泡；JSONL 进度/工具事件只算运行活动不算结论，但 `text`、`reasoning`、`step_start` 和 `tool_use` 会实时转成 assistant / thinking / tool-use 气泡。OpenCode 1.18.32 在 provider 返回前不会写 stdout JSON，插件因此追加官方 `--print-logs`，把 stderr 的 `timestamp=... level=` 日志算作启动活动且不显示为 trace；INFO/WARN/DEBUG 不当作 provider error，没有助手正文时 `level=ERROR` 的 `error.error` 要展示。stdout 为空且进程成功退出时，只调用一次官方 `opencode export <sessionID>` 恢复短回复；没有后续工具调用时，带 `time.end` 的短回复完成正文可以收口；只在启动后 60 秒连 JSON 事件和这类日志都没有时触发空输出重试，首个有效事件后不再按父 JSONL 静默超时；错误解析、空输出重试及非交互 Runner 约束以 `.ch/docs/references/cli-runtime-reference.md` 为准。配置中心不再从 Claude / Codex 生成 OpenCode 配置。
