# 选择并派发可独立交付的工作

先列出原始与补充目标中仍需交付的工作，扣除 running、pending 已覆盖的事项和有效验证已经覆盖的检查。主模型承担普通调查、分析、计划与解释。大型调查有至少两条各需实质调查的独立线索，且并行明显改善耗时或覆盖时，同轮派出至少两个 general，各给不同证据范围。general 只读，生成时省略 writeFiles 和 codingDelivery。

按交付物和主要写入范围划分实现、配置、脚本、文档与测试。任务就绪、可以独立验收、写入相容时，在空槽和单次上限内同轮派发。多项可以使用同一个子模型。只剩一个合适的边界时派一项。某个返工阻塞的范围仅限实际依赖它的工作。最终目标已满足时进入收尾。仅派返工或保留可用槽位时，在主沟通文件逐项记录未派原因，包括实际依赖、写入冲突、已被运行/排队项覆盖、暂无其它就绪交付。

写任务提供稳定 id、title、taskType、自包含 prompt 和具体的主要 writeFiles。conflictGroup 只标共享可变资源。共享契约、中心注册或同一符号指定一个负责人，或先派小前置。可使用稳定契约的独立测试和文档仍可并行。潜在的小范围顺带修改由执行者重读最新文件、保留并发变更、协调并记录原因。预期有实质竞争时重新编排。

每次 dispatch 或 reprompt 都重新判断 requiresAcceptance，省略取 true。输出不清、涉及共享契约、质量与故障归因或实质安全、隐私、集成风险，以及用户或项目要求独立复核时，必须验收。可免验的范围包括有具体命令与覆盖报告的限定测试/构建、有来源的只读取证、按指定输入机械生成报告，以及范围明确、局部可直接验证的低风险修改。例子是固定非敏感日志或局部变量重命名。共享默认值、敏感日志即便只改一行也须验收。免验仍需完成任务指定的检查，报告实际结果、未覆盖范围和失败，主任务读取并回执。Git 交付另按专题核对授权。

复用已结束的连续任务时填写 continueFromSubtaskId。独立任务省略它。仍在执行的任务需要重定向时用 controls.reprompt。宿主检查同一父任务、CLI 和配置，同一来源会话串行。依赖单独声明 dependsOn。验收前是否可 dispatch 以本轮窗口为准。
