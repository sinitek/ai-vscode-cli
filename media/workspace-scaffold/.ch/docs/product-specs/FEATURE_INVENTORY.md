# 能力索引

这个文件是当前仓库用户可见能力和平台能力的**索引**，不是验证日志。

作为 starter，这里默认从空表开始；当首个真实能力进入规划、实现、交付、暂停或下线时，再新增条目。

## 更新规则

- 新增能力时新增一行。
- 修改已有能力时只更新状态、角色、规格来源、实现入口和最近验证链接。
- 下线能力时不要直接删除，改成 `removed` 并保留历史说明。
- 如果一个能力变更无法直接链接到规格，至少要能链接到执行计划。
- 不要让 README、聊天记录、任务单、临时表格分别维护不同版本的功能列表。
- 不要把测试步骤、验证日志、问题排查过程写进本表；这些细节放到对应执行计划、测试报告或规格文档。

## 什么时候必须更新

- 新增用户可感知能力、后台能力、运维能力或平台能力。
- 修改已有能力的行为、权限、流程、入口、状态或适用角色。
- 能力进入暂停、废弃、替换、下线状态。
- 需求没有新增页面，但改变了导入导出、通知、审计、报表或批处理能力。

## 状态枚举

- `proposed`：已识别，但尚未进入实施
- `in-progress`：正在建设
- `active`：已经交付且当前生效
- `deprecated`：仍存在，但不建议继续使用
- `removed`：已下线，仅保留历史记录

## 字段边界

- `能力`：描述用户或系统能力，不直接使用页面名或接口名。
- `状态`：只使用下面的状态枚举。
- `角色`：写主要使用者、维护者或系统角色。
- `规格来源`：链接到规格文档；没有规格时临时链接到执行计划。
- `实现入口`：链接到代码目录、服务、页面、脚本或模块边界。
- `最近验证链接`：链接到执行计划验证结论、测试报告或 CI 记录；不展开验证细节。
