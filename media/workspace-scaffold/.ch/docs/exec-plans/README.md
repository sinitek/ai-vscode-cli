# 执行计划

本目录记录非平凡、多阶段、跨模块或高风险任务。这里是计划命名、分类、拆分、状态与归档规则的单一事实来源；根级 `AGENTS.md` 仅提供导航。

## 文件与类型

真实计划文件名严格为 `YYYY-MM-DD-<type>-<kebab-case-slug>.md`，日期后紧接且只出现一个 type。允许类型仅为 `feature`、`bugfix`、`refactor`、`chore`、`docs`、`test`、`perf`，不得缩写为 `feat` 或 `fix`。

| Type | 含义 |
| --- | --- |
| `feature` | 新功能开发 |
| `bugfix` | 修复已发布版本中的 bug |
| `refactor` | 行为保持的重构 |
| `chore` | 维护、构建、发布与治理 |
| `docs` | 文档工作 |
| `test` | 测试开发或测试基础设施 |
| `perf` | 性能优化 |

一个任务包含多个实质工作类型时，必须按类型分别建计划。每份计划都要有自己的目标、范围、验收标准、验证计划和真实状态；“关联计划”填写具体相对路径并记录共同背景与依赖。禁止只选主类型、混合多个 type，或复制整篇混合正文假装拆分；实际跨类型工作不得隐藏在附带事项中。仅记录验证证据不等于测试开发任务。

跨类型示例：新功能与测试开发分别记录为 `active/2026-11-11-feature-workspace-search.md` 和 `active/2026-11-11-test-workspace-search-regression.md`，两份计划用具体相对路径互链并说明依赖；各自维护目标、范围、验收、验证和状态。只执行既有测试并记录证据时，不额外创建 `test` 计划。

## 目录与状态

- `active/`：正在推进的计划。
- `completed/YYYY-MM/`：按计划日期月份归档的已完成计划，不要平铺在 `completed/` 根目录。
- `TEMPLATE.md`：新计划模板。
- `migrations/`：可选迁移审计资料，不替代计划正文或状态。

拆分不伪造完成，也不改变既有阻塞状态。只有头部状态为 `completed` 才能归档；迁移计划后更新并验证仓库内具体引用。枚举历史计划时递归扫描 `completed/**/*.md`，以完整相对路径标识。

每份计划至少记录背景、目标、范围和非目标、验收、影响面、风险、验证计划、测试结果、相关文档同步、进展与下一步。收尾时明确已验证及未验证内容。
