## 背景与边界

长对话持续追加过程消息，会增加活动 Tab 的 DOM 和渲染开销。用户要求每个 Tab 默认 500 个气泡，并可在工具设置 → AI任务配置修改；先清理最早的过程气泡，排除用户发起与非 JSON 渲染最终答复（2026-11-10 补充：JSON 最终气泡不保护）。因此 500 定义为软基准，保护优先，不能宣传为任何时候都最多 500 条。

用户后续明确选择真正删除插件内存与插件本地会话存档：宿主确认后，被清理的过程消息不再占用后续清理窗口，重开会话、提高设置或导出历史均不会恢复。外部 CLI 自己的会话日志与上下文不修改；本功能也不混同按天清理的 `historyRetentionDays`。这是插件消息的数据生命周期规则，不只是 DOM 或显示投影优化。

既有 `messageRendering.ts` 使用按 CLI/Tab 隔离的视图缓存，最多保留两个非活动视图、合计 5000 条缓存消息，并通过 `renderMessages` 复用未变化节点。这是另一层性能策略，原阈值、淘汰和增量渲染行为不变；不能把修改该常量当成本需求实现。本次不重设布局、颜色、交互模式或 CLI 完成协议。

## 配置与状态契约

| 项目 | 约定 |
| --- | --- |
| 用户入口 | 工具设置 → AI任务配置中的“每个标签页气泡上限”数字输入（范围 1–10000）；中文说明明确会永久删除插件消息及本地历史、提高上限不会恢复，不修改外部 CLI 数据 |
| 设置键与作用域 | `chatMessageLimit`，全局工具设置；同一基准对每个 Tab 独立计算，不是全局消息总配额 |
| 持久化 | 复用 `src/toolSettings.ts` 的 `~/.sinitek_cli/settings.json`，不新增工作区覆盖项或独立配置文件 |
| 归一化 | 默认 500、整数范围 1–10000；仅接受有限数字及非空且可转换为有限数字的字符串，先 `floor` 再 `clamp` |
| 无效输入 | `undefined`、`null`、空串、空白串、非数字串、布尔、数组、对象、NaN、正负无穷均回退 500；不可通过通用强制转换把它们视为 0 或 1 |

## 显示集合与批次滞回

1. 从当前 Tab 的原始消息按现有基础显示规则排除空内容、隐藏 Loop+ 协议、系统运行状态及解析后的隐藏任务列表等，保留每项原始索引；此时不应用「仅显示最终结果」。基础集合的消息项总数为 C，不按折叠指令组的 DOM 节点数计数，也不以仅可清理项的数量替代 C。
2. N 为归一化后的设置基准，H=`floor(1.1N)`，B=`max(1, ceil(0.2N))`。当 C≤H 时保留全部基础集合。
3. 当 C>H 时，最旧清理区间大小 Q=`B * ceil((C-H)/B)`。仅检查基础集合最早 Q 项，移除其中可清理的过程消息，跳过保护项。保护项占用区间位置，不越过 Q 向后补删；实际移除数是该区间内的可清理项数，不是必须删除 Q 条，也不是只截断最后 N 条。
4. Webview 将候选消息的 ID 与内容快照发给宿主。宿主成功写入存档后，原地移除缓存和运行中数组中的相同消息，再回传权威剩余集合；索引按剩余集合重新计算。随后才应用「仅显示最终结果」过滤与增量渲染。
5. 后续 C 以真正剩余消息计数，不含已经清理的消息。同一批确认后的重复渲染不向后补删；消息集合、保护状态、忙闲状态或设置变化才重新计算。等待宿主确认时只允许一个清理请求，避免重复提交。

批次滞回避免每增加一条消息就移除一条旧气泡。每次以同一原始集合和设置重算应获得同一投影，不能因重复渲染继续削减同一批数据；切换过滤也不能重置成不同的清理计数口径。

### 默认边界示例

以下均为 N=500、H=550、B=100，且最旧清理区间内没有保护项的情况；区间内有保护项时实际保留数增加相应数量。

| C | Q（区间大小） | 保留数 | 行为 |
| --- | --- | --- | --- |
| 500 | 0 | 500 | 基准以内不清理 |
| 550 | 0 | 550 | 触发线等号不清理 |
| 551 | 100 | 451 | 移除最早 100 个可清理项 |
| 650 | 100 | 550 | 尚属同一批次 |
| 651 | 200 | 451 | 下一批，累计检查最旧 200 项 |

例如 C=551 时只检查最早 100 项；其中若有 1 条用户发起与 1 条最终答复，只清理其余 98 项、保留 453 项。第 101 项及其后的指令和思考不受本批清理影响。

N=1 时 H=1、B=1，避免批量为零。N=10000 时 H=11000、B=2000；10000 是可配置基准的上限，不是承诺最大可见数。

## 最旧优先与保护优先

- 用户发起消息一律保护，不能为了凑 Q 删除原始需求。
- 最终答复保护基于主色边框使用的 `isFinalAssistantSummaryMessage`，包括助手正文的协议文本 `[final_answer]` 及 `loopAnswerConclusion`、`loopFinalSummary`、`codexFinalAnswer` 等结构化标记，但排除完整 JSON 对象/数组渲染气泡。去掉开头最终标记后，裸 JSON 或单代码围栏内 JSON（含空对象/数组、BOM、空白、CRLF、反引号或波浪线围栏）与思考/指令同等清理，尤其主任务分派子任务的最终协议气泡；不因主色边框保留。带正文说明、混合 Markdown、无效 JSON 或 JSON 标量仍按普通最终答复保护。Webview 与宿主共享 `src/shared/jsonContainer.ts`，与 Markdown JSON 树渲染判定一致。不改变最终答复样式、仅看结果过滤或 CLI 完成判定。
- 无最终标记的普通助手正文、兼容识别的思考、显式思考和指令均为过程消息，不因 `assistant` 角色或缺少 `kind` 而额外保护。清理不另设保守最终判定，不改变 CLI 完成或隐藏重试协议。
- 正在流式输出、尚待 Markdown 收尾的助手正文临时保护，不截断；结束后按是否为最终答复重新计算。处于数组末尾本身不构成永久保护理由。
- 清理区间由原始顺序决定，区间内对思考和指令同等处理，不按消息类型分别凑清理数量，不跨过区间边界向后补删。
- 区间内保护优先，保护项自身超出 H 也保留。可见气泡可能超过 500、550 甚至设置最大基准；这是显式安全取舍，不是严格内存上限。

## 真正删除与持久化确认

- 协议使用 `pruneChatMessages` / `chatMessagesPruned`，携带请求 ID 和 Tab/CLI/会话身份。宿主重新检查消息内容快照、用户/最终答复保护以及活动输出，过期请求不应用到新会话。
- 主色边框与宿主保护共用 `finalAnswerProtocol.ts` 的 `isFinalAnswerMessage`；宿主不信任前端关于可删除性的单方面判断。运行中当前助手消息临时保护，结束后可重新清理普通过程正文。
- 写入采用同目录临时文件加重命名；保存失败保留原存档和内存，回传错误恢复真实显示，不假报成功或在每次渲染中无休止重试。
- 成功后原地压缩宿主缓存、主运行、并行/交互运行及待绑定草稿的消息数组，避免旧数组后续保存把数据写回。主运行索引重定位，交互流式写入按消息 ID 重新定位。
- 存档使用兼容字段 `retentionPruned: true` 标记主动清理。Claude 在只剩用户消息时不再从外部 transcript 自动补回被清理的过程；标记随正常保存、草稿绑定和本地会话迁移保留。
- Webview 依据宿主回复替换实际运行时消息集合，后台 Tab 的回复不会覆盖前台；保留既有未变化节点、阅读锚点和指令展开状态。隐藏协议/空内容等不在基础气泡集合内，不因本功能顺带清理。

## 更新、隔离与兼容

- 计算和缓存身份沿用 CLI/Tab，A Tab 的消息量和清理不能消耗 B Tab 的额度。关闭 Tab 继续使用既有释放路径。
- 设置降低或提高后重新计算清理条件；缓存命中也必须核对当前设置，不能恢复旧集合。提高设置不能复活已经从插件历史删除的消息。
- 历史打开、全量 `setMessages`、宿主状态回传、增量消息追加/更新、流式输出与后台 Tab 更新均需覆盖，不能只在用户发送时执行。
- 后台 Tab 切回后应使用最新消息和设置，保留未淘汰节点的增量复用、可用的阅读位置和指令展开状态；其他 Tab 的滚底帧不得覆盖当前视图。
- 「仅显示最终结果」前后均先选同一基础窗口再过滤；不借该模式删保护项或更改最终结果过滤本身的语义。
