- 日期：2026-11-09

- 产品入口：[功能总表](../product-specs/FEATURE_INVENTORY.md#每-tab-聊天气泡显示限额)

## 背景与边界

长对话持续追加过程消息，会增加活动 Tab 的 DOM 和渲染开销。用户要求每个 Tab 默认 500 个气泡，并可在工具设置 → AI任务配置修改；最新补充要求一定先清理最早的过程气泡，排除用户发起与最终答复。因此 500 定义为软基准，保护优先，不能宣传为任何时候都最多 500 条。

本功能只选择面板显示投影，不从宿主持久化会话、CLI 上下文、回放或磁盘历史删除消息，不改变会话导出与恢复的数据源，也不混同历史自动清理 `historyRetentionDays`。它不是新的历史数据生命周期规则。

既有 `messageRendering.ts` 使用按 CLI/Tab 隔离的视图缓存，最多保留两个非活动视图、合计 5000 条缓存消息，并通过 `renderMessages` 复用未变化节点。这是另一层性能策略，原阈值、淘汰和增量渲染行为不变；不能把修改该常量当成本需求实现。本次不重设布局、颜色、交互模式或 CLI 完成协议。

## 配置与状态契约

| 项目 | 约定 |
| --- | --- |
| 用户入口 | 工具设置 → AI任务配置中的“每个标签页气泡上限”数字输入（范围 1–10000）；说明文案明确为全局设置且仅影响显示，不称为删除历史 |
| 设置键与作用域 | `chatMessageLimit`，全局工具设置；同一基准对每个 Tab 独立计算，不是全局消息总配额 |
| 持久化 | 复用 `src/toolSettings.ts` 的 `~/.sinitek_cli/settings.json`，不新增工作区覆盖项或独立配置文件 |
| 归一化 | 默认 500、整数范围 1–10000；仅接受有限数字及非空且可转换为有限数字的字符串，先 `floor` 再 `clamp` |
| 无效输入 | `undefined`、`null`、空串、空白串、非数字串、布尔、数组、对象、NaN、正负无穷均回退 500；不可通过通用强制转换把它们视为 0 或 1 |
| 边界输入 | 0、负的有限数钳制为 1；500.9 与 `"500.9"` 为 500；大于 10000 的有限数钳制为 10000 |
| 宿主面板状态 | `PanelState.chatMessageLimit?: number`，可选以兼容旧快照；缺失或非法值按同一归一化规则处理 |
| 实际浏览器状态 | `state.chatMessageLimit` 启动即为 500，不以可选类型造成 undefined；宿主同步、设置更新使用相同归一化语义 |
| 设置消息 | 沿用 `updateSetting`，`key: "chatMessageLimit"`；保存后由现有宿主状态链回推并重新计算显示投影 |

已落地链路为 `src/toolSettings.ts` 的全局 `~/.sinitek_cli/settings.json` 读写、`src/panelStateBuilder.ts` 的宿主状态构建、`src/webview/viewContentScript/modelAndPanelState.ts` 的浏览器状态同步，以及 `src/webview/viewContentScript/settingsAndOverlays.ts` 的数字输入绑定与 `updateSetting` 消息。输入提交会归一化并立即重算显示投影；面板状态字段可选以兼容旧快照，浏览器初始状态为 500。

## 显示集合与批次滞回

1. 从当前 Tab 的原始消息按现有基础显示规则排除空内容、隐藏 Loop+ 协议、系统运行状态及解析后的隐藏任务列表等，保留每项原始索引；此时不应用「仅显示最终结果」。基础集合的消息项总数为 C，不按折叠指令组的 DOM 节点数计数，也不以仅可清理项的数量替代 C。
2. N 为归一化后的设置基准，H=`floor(1.1N)`，B=`max(1, ceil(0.2N))`。当 C≤H 时保留全部基础集合。
3. 当 C>H 时，移除预算 Q=`B * ceil((C-H)/B)`。从基础集合的最旧项向后扫描，只移除可清理的过程消息，跳过保护项，直至达到 Q 或候选耗尽。实际移除数为 `min(Q, 可清理项数)`，不是只截断最后 N 条。
4. 保留项保持原顺序与原始消息索引，不改写原消息数组。随后才对保留集合应用「仅显示最终结果」的既有过滤，再交给 `renderMessages` 与指令分组/增量渲染。

批次滞回避免每增加一条消息就移除一条旧气泡。每次以同一原始集合和设置重算应获得同一投影，不能因重复渲染继续削减同一批数据；切换过滤也不能重置成不同的清理计数口径。

### 默认边界示例

以下均为 N=500、H=550、B=100，且有足够可清理候选的情况；保护优先时实际保留数可能更高。

| C | Q | 保留数 | 行为 |
| --- | --- | --- | --- |
| 500 | 0 | 500 | 基准以内不清理 |
| 550 | 0 | 550 | 触发线等号不清理 |
| 551 | 100 | 451 | 移除最早 100 个可清理项 |
| 650 | 100 | 550 | 尚属同一批次 |
| 651 | 200 | 451 | 下一批，累计移除预算 200 |

N=1 时 H=1、B=1，避免批量为零。N=10000 时 H=11000、B=2000；10000 是可配置基准的上限，不是承诺最大可见数。

## 最旧优先与保护优先

- 用户发起消息一律保护，不能为了凑 Q 删除原始需求。
- 所有已有明确最终标记均保护，包括协议文本 `[final_answer]` 和各 CLI 的结构化最终标记；不能仅保护当前最后一条助手消息、仅保护某个 CLI 或某一种标记。
- 对没有最终标记的 CLI，普通非思考主助手回复保守保护，避免误删最终答复；有明确过程/思考属性的消息可作为清理候选。此保护规则不把普通正文认定为 CLI 运行成功，不改变既有最终结论识别或隐藏重试协议。
- 正在流式输出的消息不截断、不从显示投影中移除；结束后按其最终内容与属性重新计算。
- 对可清理项严格按原顺序从最旧向后移除，不按内容长度、角色分桶或 DOM 缓存最近使用时间淘汰；不越过较旧可清理项去删较新的项。
- 候选不足时保留优先，保护项自身超出 H 也保留。可见气泡可能超过 500、550 甚至设置最大基准；这是显式安全取舍，不是严格内存上限。

## 更新、隔离与兼容

- 计算和缓存身份沿用 CLI/Tab，A Tab 的消息量和清理不能消耗 B Tab 的额度。关闭 Tab 继续使用既有释放路径。
- 设置降低或提高后重新计算相关显示投影；缓存命中也必须核对当前设置，不能恢复过时窗口。提高设置可重新展示仍在原始集合内的消息，不从已删历史“恢复”。
- 历史打开、全量 `setMessages`、宿主状态回传、增量消息追加/更新、流式输出与后台 Tab 更新均需覆盖，不能只在用户发送时执行。
- 后台 Tab 切回后应使用最新消息和设置，保留未淘汰节点的增量复用、可用的阅读位置和指令展开状态；其他 Tab 的滚底帧不得覆盖当前视图。
- 「仅显示最终结果」前后均先选同一基础窗口再过滤；不借该模式删保护项或更改最终结果过滤本身的语义。
