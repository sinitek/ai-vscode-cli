# Loop模式

- 日期：2026-05-01
- 状态：completed
- 负责人：Codex

## 背景

AI 对话已有编码和规划模式，需要新增“Loop模式”：由模型围绕一个目标拆分多轮执行，子任务完成后由主任务检查整体完成度，并通过本地记录文件辅助判断。

## 目标

交付一个可见、可持久、可验证的Loop模式入口与基础编排流程。

## 范围

- 聊天面板模式选择新增Loop模式，并支持中英文文案。
- Loop模式发送时沿用当前 tab 会话，不再强制重置为新会话。
- 在 `~/.sinitek_cli/` 下写入Loop任务记录文件和 `loop-communications/<taskId>/` 沟通目录，用于记录主任务、轮次、子任务概要、执行报告与状态。
- 多轮执行时将消息气泡标记为 🦞 或子任务；主任务返回 JSON 决策，扩展解析自包含 prompt 后以独立新会话启动子任务，并自动切换到子任务标签展示气泡和流式消息；子任务结束后切回主任务审核验收；验收不通过继续子任务，验收通过才结束；子任务执行出错会 1 分钟间隔重试最多 5 次；子任务完成前必须写清自己的沟通文件，主任务唤醒后读取这些文件再验收。
- 同步产品规格、功能清单与 CLI 运行参考。

## 非目标

- 不引入新的 CLI、框架或第三方依赖。
- 不改变现有 coding / plan 模式语义。
- 不实现跨 VS Code 重启后自动恢复未完成Loop任务。

- [x] 消息气泡展示“🦞 / 子任务”标记，并在子任务运行时自动切到子任务标签显示流式消息。

## 风险与缓解

- 风险：模型未按约定更新记录文件导致循环无法判断完成。
- 缓解：扩展侧限制最大轮次，并在每轮结束写入扩展观测状态；只有记录文件显式完成才自动结束。
