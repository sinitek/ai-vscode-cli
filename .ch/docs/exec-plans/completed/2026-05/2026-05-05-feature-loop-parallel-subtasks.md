## 背景

当前Loop模式主任务每轮只能返回一个 `subtask`，扩展启动该子任务并等待完成后立即唤醒主任务复核。用户要求改为由主任务判断子任务是否互不冲突；不冲突时可以同一轮并发执行多个子任务，并且必须等这一批子任务全部完成后才唤醒主任务。

## 目标

支持Loop主任务在 `status=continue` 时返回一个并发子任务批次。扩展为批次内每个子任务创建独立会话并并发执行；仅当批次内所有子任务都正常完成后，才追加主任务唤醒消息并进入下一轮主任务复核。

## 范围

- 扩展Loop主任务 JSON 协议，兼容旧的单 `subtask` 字段，新增 `subtasks` 批次字段。
- 更新任务记录与轮次记录，支持同一轮多个子任务的状态与沟通文件。
- 更新Loop主/子任务提示词，要求主任务负责冲突判断，只有无共享写入/验证冲突时才批量派发。

## 非目标

- 不在扩展侧做源码级冲突分析或自动拆分依赖图。
- 不改变 CLI 技术栈、模型配置 UI 或底层交互 Runner。
- 不实现跨 VS Code 重启后的未完成批次自动恢复。

## 风险与缓解

- 风险：多个交互式子任务同时运行时可能受已有多 tab 并发隔离影响。
- 缓解：继续使用每个子任务独立 conversation tab 和现有 `interactiveRunsByTabId` 隔离；批次调度只聚合 Promise 结果，不复用同一会话。
- 风险：模型误把冲突任务放进同一批次。
- 缓解：协议提示明确主任务负责冲突判断；扩展只信任主任务声明，不做猜测式冲突检测。
