## 验收标准

- [x] 自动压缩完成后，原 tab 运行态能正确结束，不会停留在“执行中”
- [x] 自动压缩期间点击终止能命中后端运行态，不会出现无法停止的卡死状态

## 风险与缓解

- 风险：任务收尾与自动压缩共用运行状态，可能导致结束事件和后置压缩互相覆盖
- 缓解：将后置压缩挂在任务真正收尾之后

## 决策记录

- 2026-05-21：自动压缩复用全局压缩运行态时必须设置 `activeTabIdForRun`，否则 `runStatus` 会落到前端当前 tab，而 `stopRunForTab()` 无法反查到可停止运行，导致压缩已完成但 UI 仍显示执行中
- 2026-05-21：压缩 stop 回调需要同时处理交互 runner 和底层 `activeProcess`，并在异步 cleanup 中校验 `runId`，避免停止后的旧收尾覆盖后续状态

## 当前结论

自动压缩绑定原始 tab，压缩完成或终止后运行态能正确收尾。
