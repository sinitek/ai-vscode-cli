# 龙虾并发优先子任务派发

- 日期：2026-05-05
- 状态：completed
- 负责人：Codex

## 背景

龙虾模式已支持 `subtasks` 批次并发执行，但当前主任务提示词仍偏保守：第 1 轮强调“派发第一个最小可执行子任务”，并把无法确认的场景默认串行，导致实际使用中几乎不会出现并发子任务。用户反馈希望尽量使用并发，只要能确定修改文件不可能冲突即可。

## 目标

让龙虾主任务在拆分时采用“并发优先、文件冲突兜底串行”的策略：能明确下一批子任务写入文件互不重叠、无先后依赖时，优先返回多个 `subtasks`；只有写同一文件/配置、共享不可并行验证资源或存在依赖时才串行。

## 范围

- 调整龙虾主任务提示词与 JSON 协议示例，弱化过度串行约束，强化并发优先策略。
- 为子任务决策增加可选的文件写入范围元数据，便于主任务明确说明并发安全边界。
- 同步功能规格与运行参考文档。

## 非目标

- 不改动底层 CLI 技术栈或新增依赖。
- 不实现跨进程文件锁或 VS Code 外部修改冲突检测。
- 不改变最多 6 个子任务并发的上限。

## 风险与缓解

- 风险：过度鼓励并发可能增加同文件修改冲突。
- 缓解：提示词要求每个子任务声明预计写入文件/范围；只要写入文件不重叠且无先后依赖才并发；子任务执行时只能写授权范围，发现冲突停止并报告。
