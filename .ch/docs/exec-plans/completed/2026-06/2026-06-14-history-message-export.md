# 历史消息查看与流式日志导出

- 日期：2026-06-14
- 状态：completed
- 负责人：Codex

## 背景

历史记录弹窗当前能列出历史会话和历史提示词，但历史会话只能加载或删除，不能在弹窗内直接查看该会话保存的消息，也不能从历史记录导出对应消息/流式日志。用户同时反馈操作按钮强制一行展示会挤压表格或列表空间。

## 目标

为历史会话弹窗补充历史消息查看能力，并支持从弹窗导出会话消息作为流式日志文本；同时让操作按钮可多行换行展示，避免横向挤压。

## 范围

- `src/webview/viewContent.ts`：历史会话 UI、历史消息弹窗/面板、导出入口、按钮换行样式、国际化文案。
- `src/webview/types.ts`：如需新增 webview 消息协议则补充类型。
- `src/extension.ts`：读取会话历史消息、导出会话消息文本、回传结果。
- `.ch/docs/product-specs/*`：同步功能清单与能力规格。

## 非目标

- 不改动 CLI 执行协议和底层 Runner。
- 不改变现有历史保留策略。
- 不新增数据库或外部依赖。

## 验收标准

- [x] 历史会话列表可在弹窗内查看该会话的历史消息。
- [x] 历史消息视图可按保存消息导出 TXT，失败/空数据有明确提示。
- [x] 当前运行流式消息导出能力保持可用。
- [x] 操作按钮允许换行，多按钮场景不强制撑宽列表/表格。
- [x] 中英文国际化文本齐全。
- [x] Node 项目 `npm run build` 通过。

## 影响面

## 风险与缓解

- 风险：历史消息文件可能缺失或损坏。
- 缓解：复用现有 `loadSessionMessages` 与错误提示通道，导出前做空数据校验。

- 风险：webview 弹窗状态与当前运行流式弹窗状态互相影响。
- 缓解：为历史消息导出使用独立 pending 状态和独立消息类型，不复用运行中流式弹窗状态。
