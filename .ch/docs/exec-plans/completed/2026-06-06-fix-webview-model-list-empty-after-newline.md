# 修复 Shift+Enter 后模型列表清空

- 日期：2026-06-06
- 状态：completed
- 负责人：Codex

## 背景

用户反馈 AI 对话面板底部输入框按 `Shift+Enter` 换行后，模型选择下拉选项消失；打开模型管理时列表为空并提示“模型列表状态异常”。诊断显示 webview 可见模型数为 0，但内存和磁盘 `~/.sinitek_cli/models.json` 中当前配置档案仍有模型。

## 目标

修复聊天面板中模型列表被空状态覆盖的问题，确保输入框换行、面板状态刷新或配置状态短暂缺失时，不会把已存在的模型列表渲染为空。

## 范围

本次覆盖聊天 webview 的模型状态接收、渲染与模型管理诊断链路，以及扩展侧必要的模型状态推送保护。

## 非目标

不重构配置中心，不改变 `models.json` 存储格式，不新增模型管理能力。

## 验收标准

- [x] `Shift+Enter` 换行不会清空底部模型下拉选项。
- [x] 当扩展侧短暂推送空模型数组但当前 CLI 已有模型时，webview 保留最后有效模型列表。
- [x] 模型管理打开时不会因前端空列表和存储有模型的状态不一致而误报。
- [x] TypeScript 构建通过。

## 影响面

- 代码目录：`src/webview/viewContent.ts`、必要时 `src/extension.ts`
- 文档目录：`.ch/docs/runbooks/PITFALLS.md`、`.ch/docs/product-specs/FEATURE_INVENTORY.md`
- 配置与脚本：无

## 风险与缓解

- 风险：错误保留旧模型列表可能掩盖用户主动清空模型列表的操作。
- 缓解：只在收到的模型状态和管理模型同时为空、且当前 CLI 仍存在最后有效列表时保留；用户主动通过模型管理清空时需确认对应消息路径仍能清空。

## 当前结论

已完成。根因是配置心跳/状态刷新在 active config 短暂为空时构造了空模型数组，webview 又无条件覆盖本地模型状态。修复后模型状态使用 active config 或仍存在的 workspace preferred config 读取；webview 对当前 CLI 的异常空快照保留最后有效模型列表，并允许自动应用配置按 30 秒节流重试。
