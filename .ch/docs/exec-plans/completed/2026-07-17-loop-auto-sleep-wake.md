## 背景

Loop 主任务当前只能返回 `completed`、`continue` 或 `blocked`。对于需要等待外部结果、长时间构建或异步流程的任务，主任务只能持续占用执行回合或提前结束后依赖人工继续，无法表达“暂时结束本轮，在指定间隔后自动回来复核”。

## 目标

让由宿主解析本 JSON 决策协议的 Loop 任务可以通过结构化 JSON 主动进入持久化睡眠状态，并在指定间隔到达后自动沿用现有 Loop 恢复链路继续执行；同时在 Loop 群聊中展示实时唤醒倒计时，并在 AI 对话和群聊时间线中展示可读的自动睡眠消息。

## 范围

- 扩展 `LoopMainDecision` JSON 协议，增加 `sleep`、`wakeAfterSeconds` 和 `sleepReason`。
- 扩展 Loop 任务持久化状态，保存睡眠开始时间和绝对唤醒时间。
- 增加可恢复、可取消、支持长延迟分段定时的自动唤醒控制器。
- 在扩展启动时恢复当前工作区的睡眠任务；到期后沿用现有 `runLoopPrompt` 恢复入口。
- 在 Loop 群聊展示唤醒倒计时和自动睡眠助手气泡。
- 补齐中英文文案、单元测试、设计和功能事实文档。

## 非目标

- 不增加新的技术栈、后台服务或系统级定时任务。
- 普通自由文本回复不会触发自动睡眠；只有由宿主解析本 JSON 决策协议的任务决策可以返回 `sleep`。
- 不保证 VS Code 完全退出时仍在后台启动进程；扩展下次激活后会立即恢复已到期任务。
- 不改变现有 `continue` 子任务重试、失败上限或最大 Loop 轮次规则。

## 风险与缓解

- 风险：Node 单个 `setTimeout` 延迟上限约 24.8 天。
- 缓解：持久化绝对唤醒时间，并把长延迟分段重设定时器。
- 风险：到期时原标签页正在执行其他任务或运行目标暂不可用。
- 缓解：重新读取任务状态并短间隔重试；不并发启动同一标签页，不修改持久化的原计划唤醒时间。
- 风险：人工继续后旧定时器再次触发。
- 缓解：恢复入口先取消定时器并清除睡眠字段；定时回调再次校验持久化状态和唤醒时间。
- 风险：睡眠反复重跑同一轮导致记录歧义。
- 缓解：睡眠视为暂停当前 Loop 轮次，恢复时复用现有 `resolveLoopResumeRound`，并在对话和沟通记录写入明确时间与原因。
