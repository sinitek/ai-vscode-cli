# 修复工具设置跨窗口同步

- 日期：2026-11-22
- 类型：bugfix
- 关联计划：无
- 状态：completed
- 负责人：Codex

## 背景与目标

各窗口独立缓存全局和工作区配置，旧窗口保存全量快照可带回旧值；通知开关另走 VS Code 应用设置，在线回包可能覆盖正在输入的数值。统一工具设置的数据源并修复回显。

## 范围与验收

- 全局项从 `~/.sinitek_cli/settings.json` 回显，按变更字段合并并原子写入；兼容旧的通知选择。
- 工作区项沿用按项目隔离的设置文件；同项目重开弹窗读到最新值，不重载会话，也不影响其他项目。
- 数字编辑不被异步状态覆盖，未修改的输入框不重复写入。
- 不迁移 CLI 配置档案、系统通知权限、工作区规则或会话存储。

## 影响面与风险

影响全局设置、工作区设置、面板回填和通知运行时。测试使用隔离的用户目录；验证旧用户值迁移、不同窗口按键保存、工作区隔离和保存失败行为。

## 验证计划

- `npm run build` 后运行设置存储、消息路由、Webview 和通知宿主定向测试。
- 验证本体及其单测，更新功能清单和运行时设计。

## 当前结论

已完成全局/工作区设置存储一致性修复。全局变更从磁盘最新文档按字段合并、跨进程加锁并原子替换；通知选项迁入 `~/.sinitek_cli/settings.json`，旧 VS Code 应用级值仅在对应全局字段缺失时迁移。工作区设置仍按项目写入 `~/.sinitek_cli/workspace-settings/<workspaceKey>.json`；打开设置时重读全局与当前工作区文件。已加载的工作区旧快照保存时按加载基线只应用实际差异，锁内合并磁盘新值，并保留显式字段删除。Webview 回包不覆盖聚焦输入，设置消息按序处理。
