# Loop+ 父任务存储竞争与续跑

- 日期：2026-11-28
- 类型：bugfix
- 关联计划：无
- 状态：completed
- 负责人：Codex

## 目标与范围

普通 Loop+ 在任务归属事务繁忙时保留原派发。群聊能展示已提交的进度，恢复说明采用当前派发证据。任务迁移、部门归属、停止信号和提交版本仍参与执行前验证。

## 验收与验证计划

- [x] 竞争超过短退避后可等待、取消和恢复，业务失败次数准确，执行至多启动一次。
- [x] 普通内容写入和快照展示缩短全局事务，两个宿主并发修改时保留正确归属和文件版本。
- [x] 续跑时历史中断摘要与当前派发可区分，已开始或不确定的派发按原恢复规则核对。
- [x] 运行 `npm run build`、相关 Node 测试及隔离任务目录的并发验证，同步功能清单、设计与 ontology。

## 影响面与风险

涉及身份目录、普通存储、部门准入、Loop+ 调度与群聊。重读需验证完整文件版本，旧宿主与多进程写入需要共享互斥规则。验证使用隔离数据。业务任务的模型调用和交付独立于本修复。

## 实施与兼容

新派发在父记录保存 `waiting`，通过部门准入并按版本认领为 `claimed` 后才启动。冷启动巡检只接手已确认的待启动派发。普通群聊使用已提交快照，续跑操作按原编辑器绑定读取权威记录。归属映射相同时，普通进度更新在锁外准备文件，最终原子替换与旧宿主共用短写锁。中断说明按逻辑子任务的最新派发展示宿主错误，另列上次保存的说明。
