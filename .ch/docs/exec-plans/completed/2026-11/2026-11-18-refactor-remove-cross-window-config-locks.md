## 背景

跨 VS Code 窗口配置互斥及任务执行租约会让配置写入或任务启动等待，极端情况下还可能因锁清理问题长期阻塞。用户明确选择移除全部该类保护，接受其他窗口极短暂替换配置的低概率。

## 目标

跨窗口不再等待配置锁，也不以共享选择快照或执行租约阻止任务；操作按各自实际读取时的配置继续。

## 范围

- 移除跨进程配置文件锁、共享执行租约及其调用。
- 移除启动前基于 UI 选择快照/共享选择状态的陈旧拒绝。
- 清理档案切换、保存、删除与 Codex 信任写入中的跨窗口锁及活跃任务阻断。
- 保留原子文件替换、进程内串行应用及必要的读回校验。
- 更新回归测试、产品清单、运行时/设计文档及 Ontology。

## 非目标

- 不改变原生 CLI 配置的格式、备份或应用校验。
- 不保证两个窗口同时写同一目标时不覆盖；允许最后完成的写入生效。
- 不调整 runner 的配置指纹隔离及连接生命周期。

## 风险与缓解

- 风险：两个窗口同时写入同一原生配置时可能覆盖彼此。
- 缓解：保留单次写入的原子替换，尽量避免半文件；接受短暂竞争造成的最后写入生效。
- 风险：若仅删除锁实现但保留 `ready` / 选择校验，任务仍可能被共享状态拒绝。
- 缓解：同步清除入口校验，并以陈旧快照回归测试覆盖。
