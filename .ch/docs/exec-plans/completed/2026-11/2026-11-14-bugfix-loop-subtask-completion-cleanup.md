# Loop / Loop+ 子任务完成收尾顺序与关页

- 日期：2026-11-14
- 类型：bugfix
- 状态：completed
- 负责人：Codex

## 背景与目标

子任务成功后频繁遗留 Tab。统一先持久化并回报主任务，再按既有开关和时长条件压缩子会话，最后确认关闭原标签。主任务验收和独立会话不等待压缩；失败、中断和回报失败保留现场。

## 范围与验收

- 覆盖经典 Loop、Loop+ 自动完成和人工续接。
- 压缩成功、失败或跳过后均执行成功任务关页；同会话在收尾期间继续串行。
- 关页以完成时标签快照为界，保护新 attempt、换绑标签、其它任务及仍在运行的任务。
- 关闭未生效不记录成功，记录可定位的失败。
- 保留本轮开始前已暂存的 Loop+ 修复，不发布扩展。

## 已确认事实与风险

- CodeGraph 与磁盘源码：Loop+ adapter 在完成事件应用前关页；经典 lifecycle 放行后台压缩后立即关页。
- 共享关页遇到活跃任务直接跳过，调用者仍记录 auto-closed；压缩和异步关页间需要标签身份保护。
- memory-recall focus 为 Loop Loop+ 子任务 完成 回报 压缩 关闭 tab，anchor 为空；热区仍为占位，以当前设计和源码为准。
- 风险：后台收尾不能阻塞验收或误关替代调用；复用会话压缩 flight 和标签快照控制边界。

- `npm run verify:loop-plus` 使用隔离 HOME 和本机模拟模型完成本机 CLI 验证。
- ontology 校验与对应技能单测、`git diff --check`。
