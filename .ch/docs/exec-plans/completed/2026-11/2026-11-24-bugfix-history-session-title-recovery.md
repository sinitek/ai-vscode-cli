# 历史会话标题恢复

- 日期：2026-11-24
- 类型：bugfix
- 状态：completed
- 负责人：Codex
- 关联计划：无

## 背景与目标

历史会话会隐藏 Loop+ 内部协议提示，但旧逻辑命中首条内部提示后只查任务绑定，不继续查同一会话的后续消息，导致有正常用户提示的旧记录显示为「未命名会话」。

## 范围与验收

- 已绑定任务的有效 `rootPrompt` / 子任务提示保持优先；旧缓存缺失、空白或为隐藏协议时，再从同一 CLI 会话消息中恢复首条非协议、非 `loopAsk`、非空白的用户提示。
- 恢复结果持久化回填 `firstPrompt`，修复空、未命名或精确协议标签，不覆盖自定义标题；无可用来源仍显示「未命名会话」，原始消息与角色不变，不删除记录，不发布插件。
- 回归覆盖缓存有无、主/子任务绑定、无提示、空白/协议任务提示、`loopAsk`、空白消息、重复投影持久化、自定义标题和 CLI 隔离。

## 影响、风险与验证

- 影响扩展宿主历史会话投影与历史列表搜索。保留 CLI/会话身份隔离，避免把内部协议或澄清标记当标题。
- `npm run build` 通过；定向 Node 测试 328 项通过（历史投影、会话任务、生命周期、CLI 切换及 Webview 历史列表）；ontology `--validate` 通过。
- 功能清单、能力说明和 `plugin.rule.history_session_subtask_filter` 已同步。没有启动真实 CLI 或真实 Webview；本次逻辑由 Extension Host 投影单测和 Webview 静态/运行测试覆盖。

## 当前结论

根因是历史投影只在 `firstPrompt` 缺失时查找消息的第一条用户提示；当首条消息为 Loop+ 内部协议时，过滤后直接回退，未继续扫描同一会话后续的真实用户提示。现在仅对缺失、空白或隐藏协议缓存启用恢复，并在有效任务绑定和同会话消息之间维持确定的优先级。没有可恢复消息时保持未命名标签。
