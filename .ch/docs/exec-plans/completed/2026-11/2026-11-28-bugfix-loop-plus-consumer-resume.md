# Loop+ 验收期间写入与暂停续跑

- 日期：2026-11-28
- 类型：bugfix
- 状态：completed
- 负责人：Codex
- 关联计划：无

## 背景与目标

主审返回 `accept` 后，同一宿主先记录了 `host-route / identity-lock-present`，随后目标任务因更新未确认而暂停。任务记录已经保存失败结论和同 ID 返工义务，还有三个此前已启动的 attempt。现场锁日志缺少关联任务 ID 和具体写入步骤。群聊前次请求已取得启动回执，主对话发送“继续”显示了忙提示的内部键名。

## 范围与验收

- 普通任务大记录的更新缩短全局身份事务临界区，实际提交时仍校验身份、源版本与迁移。对准入后的写入区分可确认的锁竞争和其它提交失败。
- 群聊在本次父调度暂停后释放续跑请求，已启动子任务的清理观察独立延续。父任务暂停时可继续，真正运行的主任务仍受并发保护。
- 主 Tab 的输入准入区分父任务与子任务的活动，发送时使用已绑定任务的真实状态。
- 用隔离存储、受控运行句柄和现有界面入口验证，保护验收队列、在途 attempt 与用户数据。

## 实施结果

普通更新提前准备写入内容，已知来源的读取在锁外解析，一次标签投影复用同一父记录。`accept` 逐步确认持久化结果，只有可识别的身份锁竞争进入退避和分钟巡检。每次恢复核对任务来源、调度代次、计划和权威快照，提交时核对版本。已提交的验收、通知与返工登记各执行一次。

续跑调用按本代父任务暂停结果返回，清理观察继续覆盖活跃子任务。暂停主任务的输入准入使用主调用实际运行状态和待确认发送，关页仍按整个任务判断。

## 验证结果

- `npm run build` 通过。隔离存储的 `loopPlusHandoffContracts.test` 覆盖 11 个验收争锁和撤销场景，包括读取、结论、进度、返工登记、启动预留、持续锁、停止、来源切换、权威批次变化、方案变化和写入时版本被替换。
- 存储、Loop+ 编排与运行时、群聊、会话标签、宿主发送和 Webview 相关集合共 1,191 项通过，失败和跳过均为 0。覆盖父调度已暂停但子进程仍需清理、暂停记录短时不可读，以及主对话按原 Tab 和任务 ID 提交并接收确认。
- `node scripts/loop_plus_protocol_regression_smoke.cjs --scenario=group-continue-panel` 在隔离 macOS Extension Development Host 通过。实际群聊页续跑后仍绑定原任务，重复点击只产生一次主调用，宿主退出码 0。
- 调度设计、功能清单、本体和排查手册已同步。`search_ontology.py --validate` 通过。验证使用工作区构建与合成任务，现场任务仅作定向只读核对。
