# Loop 子任务先汇报再压缩

- 日期：2026-11-06
- 状态：completed
- 类型：feature
- 负责人：Codex

## 背景与目标

Loop / Loop+ 子任务的运行入口等待自动压缩后才返回，导致完成汇报与主任务验收被压缩阻塞。调整为先提交子任务完成结果，再后台压缩子任务自己的会话。

本计划只交付新的通知/压缩时序及会话隔离能力，归 feature；不将原等待路径称为未经原文证明的已发布版本 bug。

## 验收标准

- 完成结果在子任务自动压缩启动前上报，主任务可独立继续运行。
- 压缩使用独立运行状态，不覆盖主任务状态或耗时。
- 同一子任务会话的后续续接等待后台压缩；不同会话不等待。
- 后台压缩异常不撤销已上报的完成状态，不产生未处理的 Promise 拒绝。

## 影响面与风险

- 代码：运行时收尾、子任务生命周期、Loop+ 完成事件、上下文压缩依赖与会话互斥。

## 决策记录

- 2026-11-06：采用先提交完成汇报/验收事件，再启动独立压缩；保留原子任务会话级互斥，并让关闭展示 Tab 不提前销毁待压缩 runner。
- 2026-11-06：后台压缩复用原执行配置、模型与思考快照并重新获取已有配置租约；沿用同档案 revision 更新兼容规则，不新增版本硬门禁，档案切换则跳过压缩。
- 2026-11-06：OpenCode 后台压缩不得通过全局会话接管改变当前主会话；返回不同会话身份时按失败处理并保留原子任务记录。

## 当前结论

已完成。原路径确实先等待压缩再返回子任务结果；现在 Loop / Loop+ 都先提交子任务完成结果，再后台压缩子任务会话。主模型可继续调度或验收，同一子任务会话的后续运行仍等待压缩完成。自动压缩开关、成功且超过五分钟的条件和三分钟超时保持不变。

没有页面或外部协议变更，历史未运行真实模型付费验证和浏览器验收，未执行发布脚本；不补造 Windows/Linux 原生环境已验证结论。本轮只拆分历史记录，不把 completed 推导成真实 CLI 全链路成功。
