# Marketplace 发布触发来源排查

- 日期：2026-11-04
- 状态：completed
- 负责人：Codex

## 背景与目标

用户发现两次非本人直接运行发布脚本的发布，要求核查最近两小时 AI 执行日志，以及 Git 推送是否可能触发发布。

## 范围与非目标

- 范围：只读核查发布入口、Git hooks、仓库自动化、相关 AI 工具调用及结果，区分真实发布与构建或测试输出。
- 非目标：不运行发布脚本，不推送，不修改运行时代码、凭据或配置；不将原始日志和私有运行时数据写入仓库。

## 验收标准

- 明确记录核查时间窗与覆盖的日志来源。
- 发布判断同时核对命令和结果，不把代码文本、测试夹具或打包钩子误判为市场发布。
- 对 Git 推送关联给出证据边界；证据不足时明确说明。

## 影响面与风险缓解

- 代码、配置与脚本：不修改。
- 文档：仅本执行计划，记录脱敏后的方法和结论。
- 风险：日志包含凭据或无关项目隐私；仅提取当前项目相关事件，输出脱敏，不读取凭据存储。

## 验证计划与清单同步

- 最小验证：本机文件、日志结构化解析、Git hooks 与仓库自动化静态检查。
- 单元测试：不新增、不运行；本次为只读审计，不执行可能产生副作用的测试。
- 构建：不运行，避免清理当前构建产物。
- 失败处理：记录日志缺失、时间窗外事件和无法从本机证明的远端状态。
- 功能清单与 ontology：不改变功能或业务语义，无需更新。

## 当前进展

- 已核对当前发布脚本及其导出依赖，发布依赖显式调用市场上传命令。
- 已检查本地 Git hooks 与可见仓库自动化。
- 已交叉核对相关 AI 原始工具调用、结果、插件日志与终端命令历史；原始运行时证据及脱敏报告留在仓库外，通过最终答复交付。
- 当前本机证据不足以确定发布执行者，不能将市场版本变更与某次推送或打包强行关联；公司远端 Git 服务的独立自动化不属于本机可见范围。
- 已确认发布脚本没有执行前确认；末尾等待 Enter 是执行结束后的窗口保留机制，不是发布授权。
- 不修改业务语义，不更新功能清单、ontology 或热区记忆；未确认因果不写入事件记忆。
- 验证只涉及只读查询与文档检查，没有运行发布、推送、构建或测试。
