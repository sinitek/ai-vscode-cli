# CLI 进程启动与 Loop+ 决策解析重构

- 日期：2026-11-24
- 类型：refactor
- 关联计划：无
- 状态：completed
- 负责人：Codex

## 背景

CLI 运行时的进程启动与输出捕获各自组装启动选项；Loop+ 决策解析的 JSONC 回退与 `src/shared/jsonObject.ts` 的共享解析能力重复处理注释和尾逗号。两处均可先核对行为差异，再归并相同的逻辑。

## 目标

用两处局部重构减少重复实现，保持公开接口、用户可见行为和业务语义不变。

## 范围

1. `src/cli/cliProcessRuntime.ts`：归并进程启动与 `captureCliProcessOutput` 中相同的命令、启动选项和环境组装；两条路径各自的选项差异及生命周期处理留在调用处。
2. `src/loopPlusDecision.ts`：在 `parseLoopPlusJsonObject` 的 JSONC 回退中复用 `src/shared/jsonObject.ts` 的现有能力；先确认共享入口的根对象校验和语法容错与当前回退兼容，只归并等价部分。

## 非目标

- 不重写进程生命周期或决策对象提取、协议校验及反馈；不为归并而改变共享 JSONC 调用方的解析行为。
- 配置导入 UI 候选只存在于编译产物 `media/config/assets/config-app-ui.js`，仓库没有对应源码入口。不直接修改产物，也不把它作为第三处重构交付。
- 不改变用户可见行为或业务概念；不更新产品规格、功能清单或 ontology。

## 验收标准

- [x] 启动和捕获复用等价的组装逻辑；命令及参数、`cwd`/`PWD`、环境覆盖顺序（含仅启动路径使用的 overlay）、登录 shell 环境处理以及各路径的 `stdio` 和平台选项保持不变。
- [x] 流式回调、捕获输出、退出码、错误、超时及进程清理仍由原路径处理，行为不变。
- [x] Loop+ 保持严格 JSON 优先，仅在回退时复用共享 JSONC 能力；既有注释和尾逗号支持、非法输入拒绝、候选选择、协议检验与反馈均不变。
- [x] 独立只读验证子任务已执行下列定向命令并记录实际结果。

## 影响面

- 代码目录：`src/cli/cliProcessRuntime.ts`、`src/loopPlusDecision.ts`；复用边界为 `src/shared/jsonObject.ts` 的现有能力，不改变其公开契约。
- 文档目录：本执行计划；没有产品规格或 ontology 同步项。
- 配置与脚本：无；不修改生成产物。

## 风险与缓解

- 进程路径：复用时可能误把 overlay、`stdio` 或清理策略应用到另一条路径。仅提取共同组装逻辑，逐项比对平台选项及覆盖顺序。
- 解析路径：不同 JSONC 实现可能对空元素、多余逗号或不完整注释有不同处理。先核对接受和拒绝边界，再复用等价入口；若无法保持语义，不扩大容错或改动共享调用方，保留该差异并交主任务审查。
- 回滚：两个候选保持独立，出现回归时撤回对应的归并，不牵连另一处。
