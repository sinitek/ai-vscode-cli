# 主任务自动压缩期间的群聊续跑

- 日期：2026-11-28
- 类型：bugfix
- 关联计划：无
- 状态：completed
- 负责人：Codex

## 背景与目标

主任务自动压缩占用原会话时，群聊继续可能在进入主任务队列前被活动标签守卫拒绝。让一次点击在压缩完成后通过原有续跑入口重新申请执行。

## 范围与验收

- [x] 主任务压缩进入已有的每标签页执行队列，排在本轮之后、后续会话调用之前。独立子任务可以并行派发。
- [x] 群聊续跑等待压缩，重复点击只启动一次。显式停止、目标变化或任务完成使旧请求失效。
- [x] 用同一会话的可控压缩、群聊消息入口和独立标签验证时序，运行构建、相关回归与本体校验。

## 影响面与风险

涉及主任务队列、宿主调度、群聊协调器、功能清单和本体。压缩在原主调用交回队列后执行，避免等待自身持有的队列位置。恢复时重新核验工作区、会话和任务状态。身份目录的写入重试策略是独立问题。

## 验证计划

使用 `npm run build`，执行编译后的主任务队列、自动压缩与群聊续跑单测，运行 `search_ontology.py --validate`。用隔离运行验证会话和标签行为。

## 当前结论

`npm run build` 通过。主任务队列、群聊、运行适配和压缩相关的 15 个测试文件共 521 项通过。通过可控的 Codex 和 OpenCode 压缩验证主会话排队及独立标签并行。隔离的 macOS Extension Development Host 群聊页面验证重复点击只触发一次主调用。功能清单、会话复用设计和本体规则已同步，`python3 .agents/skills/ontology/scripts/search_ontology.py --validate` 通过。

扩大验证时，`loopPlusHandoffContracts.test.ts` 的最终写盘失败注入断言未命中。该夹具按文件路径匹配 `writeFileSync`，当前任务存储传入文件描述符。在保留当前存储实现、将本次变更的四个生产模块换回已安装版本的隔离对照中复现同一断言。记录归类为独立的存储测试夹具问题。
