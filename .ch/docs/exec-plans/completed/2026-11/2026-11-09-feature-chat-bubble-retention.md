## 历史实施与证据

以下从同一来源按责任分配；历史范围/任务表中涉及关联类型的措辞仅说明当时协调或验收背景，以本文上面的单类型范围为准，不重新认领已拆走的交付。

### 背景

用户要求每个 Tab 默认显示 500 个气泡，可在工具设置 → AI任务配置修改；补充要求一定优先清理最早的过程气泡，排除用户发起和最终答复。现有两个非活动视图/5000 条 DOM 缓存是不同层次的性能机制，不能代替本功能。

### 目标

在完整历史不删除的前提下，为每个 Tab 增加可配置的显示软基准、批次滞回与保护优先。稳定契约见[设计记录](../../../design-docs/chat-bubble-retention.md)，用户能力见[功能总表](../../../product-specs/FEATURE_INVENTORY.md#每-tab-聊天气泡显示限额)。两项实现、回归和文档门禁均已由记录证据覆盖；本计划归档不改变父任务调度状态。

### 范围

- 全局工具配置、面板状态传递、浏览器初值与设置入口，当前 Tab 的显示投影及各类更新路径。

### 接口约定

- 设置键 `chatMessageLimit`，写入全局工具 `~/.sinitek_cli/settings.json`，默认 500、整数 1–10000；数字及非空数字字符串在有限时 `floor/clamp`，空值、无效类型及非有限数回退 500。
- `PanelState.chatMessageLimit` 可选以兼容旧快照；实际浏览器 `state.chatMessageLimit` 默认 500。沿用 `updateSetting` 和现有宿主回推链路，不增加工作区级覆盖。
- N 为基准，H=`floor(1.1N)`，B=`max(1, ceil(0.2N))`。基础可展示原始消息总数 C≤H 不清理；C>H 时移除预算 `B * ceil((C-H)/B)`，从最旧向后只移除可清理项、跳过保护项，保留剩余原顺序及索引。
- 默认 550 条不清理；候选充足时 551 条移除 100、保留 451，650 条保留 550，651 条进入下一批、保留 451。候选不足时实际移除更少。
- 保护用户发起、所有明确最终标记、无标记 CLI 的普通非思考主助手回复及正在流式输出的消息。保护本身超限时保留优先，不承诺任何时候最多 500；保守保护不改变 CLI 完成协议。
- 先基础集合保留窗口再「仅显示最终结果」过滤；Tab 隔离，设置变化、历史加载、前后台与全量/增量更新均适用。只改变显示投影，不删除宿主持久化会话、CLI 上下文、回放或磁盘历史，不混同 `historyRetentionDays`。

### 非目标

- 不清理磁盘历史、CLI 上下文、会话存储或回放；不修改历史自动清理策略。
- 不将 5000 条非活动 DOM 缓存改成 500，不替换既有增量渲染，不重设 UI 布局/颜色/交互。
- 不新增 CLI 最终结论协议、不用保守保护改变任务成功判定；不做通用图谱重构或无关修复。
- 不运行发布脚本、不发布、不提交或推送；不写无复用价值的滚动摘要或事件记忆。
