# 经典 Loop 运行中增派与单项取消

- 日期：2026-11-20
- 类型：feature
- 状态：completed
- 负责人：Codex
- 关联计划：无；保留当前工作区已有部门会话修复。

## 目标和范围

普通经典 Loop 与产研部总监可在子任务运行时处理补充需求并增派独立工作。群聊可取消单个未结束的经典子任务或组长模块，不牵连兄弟任务。产研部取消后使用新模块 ID 重派，保留旧组长记录。

## 验收与风险

- 补充需求保存后唤醒调度；同一主会话不重入。
- 重复 ID、明确写入冲突和来源会话冲突不得提前启动；模型仍负责判断业务依赖。
- 取消不得被迟到结果覆盖，也不绕过部门 Owner、运行容量、清理凭证及最终完成门禁。
- 不改变普通 Loop+ 派发策略、不回滚既有文件改动、不操作用户当前任务。

## 验证计划

覆盖经典状态机增量派发、范围冲突以及部门单组取消与容量释放；运行定向测试、`npm run build`、Ontology 校验。

## 当前结论

经典 Loop 已改为同一主循环串行处理补充唤醒，同时由宿主持有后台批次并保留 watchdog；冲突派发延迟重新评估，取消确认真实 runner 退出且阻止迟到回调覆盖。产研部总监补充需求走专属唤醒，活动组长冲突不覆盖模块；群聊单组取消等待清理和 idle 后释放容量，将旧模块标记跳过，故障组长可用新模块重派。已同步部门设计、功能清单与 Ontology。

验证：`npm run build` 通过；Loop/部门定向回归 189 项通过，部门会话绑定与生产投影相关回归 137 项通过；产研部单组取消集成用例通过；Ontology 校验通过，Ontology Python 测试 9 项通过；`git diff --check` 通过。未在真实 VS Code Extension Host 或用户当前任务上执行验证。
