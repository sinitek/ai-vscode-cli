## 本次关联执行记录：同一主任务有界纠错

- 根因：格式失败与可解析决策失败分别计数；前者指数退避直到安全上限，后者默认只纠正两次。部分报告校验缺少预期 ID，且无可领取的验收批次时不能依赖验收队列自动唤起纠错。
- 目标与验收：兼容注释、尾逗号等无损 JSON 写法；真正无效的回复在同一主任务会话收到最新拒绝原因和批次，格式、字段与调度拒绝共用最多三次纠错额度。第三次纠正成功可继续，仍失败才进入待复核；停止、全局安全与真实完成门禁保留。
- 验证计划：解析与提示单测、同主会话混合错误和冻结批次回归、构建、Ontology 及差异检查；不发布、不操作现有用户任务。
- 实现：JSONC 仅去除注释与尾逗号，再由 `JSON.parse` 和现有业务校验处理；格式、字段及调度失败共用三次额度。请求附次数、最近原因、有限长度旧对象和最新快照。冷恢复只读取摘要的实际拒绝原因，且带补充需求时不再先发一个看不到补充内容的初始请求。
- 结果：`npm run build`、Loop+ 及共享提取器回归 653/653、Ontology 校验及 9 项脚本单测、`git diff --check` 通过。回归覆盖混合错误第三次成功、持续无效暂停、停止、安全上限、持久冻结批次和重载带补充说明恢复。测试初轮两处断言仍按旧次数喂回复，后续补齐；冷恢复新用例另外捕获初始请求遗漏补充内容，已修正并全量重跑。日志：`.tmp/loop-plus-repair-tests.log`。
- 本节的实现、回归及主任务验收已完成。运行时适配器集成使用受控 CLI 输出，未调用真实在线模型，未修改或恢复原任务状态。
