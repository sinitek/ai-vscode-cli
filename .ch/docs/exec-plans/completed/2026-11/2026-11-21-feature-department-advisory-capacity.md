# 产研部派发建议与 Loop 协作

- 日期：2026-11-21
- 类型：feature
- 状态：completed
- 关联计划：`.ch/docs/exec-plans/completed/2026-11/2026-11-21-bugfix-department-leader-receipt-observation.md`。两项工作均来自产研部故障排查。

## 目标与验收

- 组长、员工和分组额度及余额只随决策提示提供给模型。零余额、余额未知或请求超过参考额度时，派发数量由模型决定。
- 按实际执行身份登记占用。核对任务身份、代次、重复请求、原调度器冲突规则及清理证明，兼容旧执行快照。
- 组长基于普通 Loop+ 完成结果结算。总监基于原始目标、组长汇报及最新需求作出经典 Loop 完成判断。
- `departmentCollaborations` 与 `directorCollaborations` 分别附加在当前有效 Loop+ 和经典 Loop JSON 中。协作格式和投递结果单独记录，宿主核对同部门目标和消息 ID。
- 更新设置文案、功能清单、设计与本体。保留历史测试记录。

## 验证结果

构建、216 项定向测试、13 项验证脚本测试和本体校验通过。生产组合回归覆盖零额度及未知额度派发、普通 Loop+ 直接完成、组长验收时附带协作、异常协作字段、跨部门目标拒绝、总监仅处理选中 JSON 中的协作及未启动可选模块时的业务收口。隔离 macOS VS Code / Codex 工作区表单保存零值后实际派发两个员工，五份原 Owner 回执齐全并归还占用。验证报告为 `/tmp/sinitek-department-final-eh.json`。

广域回归 1371 项中 1366 项通过，五项失败已在干净基线复现，详见关联修复计划。隔离验证使用本机确定性模型响应。
