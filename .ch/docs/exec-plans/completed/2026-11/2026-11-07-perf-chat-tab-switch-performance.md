## 历史实施与证据

以下从同一来源按责任分配；历史范围/任务表中涉及关联类型的措辞仅说明当时协调或验收背景，以本文上面的单类型范围为准，不重新认领已拆走的交付。

### 背景与目标

用户反馈 AI 对话面板切换 tab 卡顿数秒。当前点击、宿主 state 回传和 setMessages 回传均可触发完整消息重建；先以生产 Webview 和合成长对话测量，再减少重复渲染及往返切换重建。

### 范围与非目标

- 非目标：不更换技术栈、不修改 CLI 执行语义、不发布扩展、不读取真实会话数据。

### 验收标准

- 相同会话的 state / setMessages 回传复用未变化消息，不重复解析 Markdown 或重建节点。
- 常用标签往返切换复用消息视图，缓存有明确数量上限且关闭标签后释放。
- 变更消息、跨 CLI 同名消息、任务状态、折叠状态和滚动位置正确隔离。
- 相关单元测试、`npm run build` 和真实 Chromium 合成长对话切换验证通过，记录前后数据。

### 影响面与风险

- 代码：`src/webview/viewContentScript/` 和已有 Webview 运行时测试。
- 风险：缓存陈旧、隐藏 DOM 占用内存、标签关闭后残留；以渲染快照对比、有界淘汰和回归测试缓解。
- 回滚：撤销本次渲染缓存与增量同步修改，不涉及磁盘格式迁移。

### 验证计划与记录

- 浏览器：headless Chromium 加载生产 HTML，使用合成会话测量点击及 state / setMessages 回传，检查浏览器错误与状态隔离。

### 实现与自动化回归

- 点击、`state` 和 `setMessages` 不再连续全量重建相同消息；复用既有增量渲染与消息内容/元数据快照。
- 两个非活动视图使用 LRU 缓存，合计最多 5000 条可见消息；关闭标签清理缓存，超大视图不进入缓存。
- 保留标签阅读位置和指令组展开状态，重新注册思考气泡 ResizeObserver；旧标签的自动滚底帧校验目标标签。
- 渲染身份与思考格式均取目标标签的 CLI，防止跨 CLI 本地点击和宿主回执之间错用格式。

### 验证结果

- 浏览器：本机真实 headless Chromium 加载生产 HTML 与完整运行时，用 Webview API 桥接桩同步模拟宿主消息；2000 条合成消息、两个标签、六次交替切换。覆盖消息总数、往返节点复用、宿主回执不重建节点及零页面/控制台/Webview 错误。检查 1100×850 与 420×850 截图。
- 为排除已有 `dist/` 陈旧影响，基线将任务起点提交 `57365e7c` 的五个相关脚本即时转译并在进程内替换，使用相同生产 HTML、夹具与 Chromium；未覆盖工作区源码。

### 失败分类与处理

- 首轮核心回归发现切换结果过滤模式被当成新会话滚到底部，属于实现缺陷；视图身份改为只含 CLI/标签，过滤模式进入渲染快照，原滚动回归恢复通过。
- 浏览器首次启动缺少 headless-shell 缓存，属于环境问题；复用已安装 Chromium 的 `channel: chromium`，未安装新依赖。
