# Loop+ 验收更新总体进度并展示主任务百分比

- 日期：2026-11-08
- 状态：completed
- 负责人：Codex

## 目标与范围

Loop+ 主模型在每次确认验收批次时，重新判断原始与补充需求的总体完成度，返回整数 `progressPercent`。成功确认后持久化为任务的 `loopPlusProgressPercent`，群聊左侧显示“主任务 23%”；最终完成落盘后为 100%。

- 范围：Loop+ 决策解析与提示、验收策略、任务存储、群聊状态投影、相关测试和文档。
- 非目标：经典 Loop 行为不变；不按子任务数或验收次数推算；不改变并发、验收门禁和前一任务的标题修复。

## 验收标准

- 生产 Loop+ 的 accept 必须给出 0–99 的整数进度，无效或遗漏时走协议重试，不确认验收、不更新进度。
- 仅在事件 ID、验收上限及控制预检通过且验收提交成功后保存新进度；拒绝、迟到回答和等待不得覆盖旧进度。
- 主模型每轮可见上次进度，必须结合需求覆盖与剩余工作评估，补充范围后允许重新校准，不伪造单调增长。
- 新任务与缺失字段的旧任务默认显示 0%；完成仅在最终完成门禁和持久化后为 100%；失败、暂停、停止保留此前进度。
- 任务重载保留进度；群聊左侧成员标题随状态更新，经典 Loop 和历史 transcript 标题不变。
- 构建、相关回归、ontology 校验通过；Chromium 未单独运行，静态 HTML 与状态更新由群聊面板回归覆盖。

## 实施与风险

- 复用既有 accept 策略和任务记录更新通道，不新增百分比计数器或前端状态源。
- 解析器采用显式严格进度选项供生产宿主启用，保持默认解析兼容旧协议；提供字段时始终严格校验类型和范围。
- 前一轮“纠正重派同步更新标题”的未提交改动保持原样。
- 风险：模型未按新协议返回进度会重试；更新所有主模型提示与示例，明确 100% 仅属于已完成状态。
