## 背景

Loop+ 子任务实现者的验证有助于复用有效证据，但不能替代主任务对交付物、冻结验收事件和最终需求覆盖的独立审查。需要明确报告内容及结果复用范围，避免重复验证和把自测误作验收。

## 目标

固化可复用的子任务验证报告与 Loop+ 主任务独立验收边界，不降低现有验收及完成门禁。

## 范围

- 设计文档与能力文档说明自检、报告、验证复用和主任务独立验收之间的边界。
- 核对功能清单中已记录的验收行为，并同步本次 Loop+ 协作标准。

## 非目标

- 不改运行时验收逻辑、六项默认审查、冻结验收顺序、报告确认、依赖或完成门禁。
- 不要求重复运行仍覆盖当前改动的有效检查。
- 不以此计划的子任务自检替代主任务对本计划交付物的独立验收。

## 验收标准

- [x] 报告逐项记录检查范围、命令/操作、结果、未覆盖项及检查后相关改动。
- [x] 明确有效验证可在仍覆盖当前交付时复用；后续改动造成失效时只补受影响检查。
- [x] 明确主任务仍独立审查交付物、需求覆盖及原验收事件，且自检不放行完成门禁。
- [x] 相关功能清单已有准确内容时保留既有事实，仅补本次未记录的规范。
- [x] 不改任何运行时语义、状态或调度数据。

## 风险与缓解

- 风险：将自检报告误作验收，或因重复验证扩大成本。
- 缓解：明确主任务独立审查责任，并按验证有效性与缺口决定最小补测范围。

## 验证计划

- 最小相关验证：核对文档链接、模板结构、`git diff --check`。
- 单元自测命令：不适用，范围仅为文档。
- 扩展验证：不运行产品测试；本计划不变更代码。
