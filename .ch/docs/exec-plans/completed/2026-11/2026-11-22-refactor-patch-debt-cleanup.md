## 背景

近期维护为修复局部行为，留下了三组可由当前事实直接确认的重复实现：部门容量快照在两条控制路径重复校验；全局和工作区设置使用重复的同步文件锁协议；OpenCode 一次最终输出解析对同一 JSONL stdout 重复解码。这些位置有明确共同不变量，且可以局部整理，不需要推断更大范围的历史代码质量。

## 目标

最多重构上述三个位置，消除重复规则，同时保持既有行为、持久化格式、执行顺序、平台兼容和失败关闭语义。

## 范围

- 将部门容量快照“匹配根 ID 且结构合法”的判定提取为共享纯校验，供群聊投影与组织停止/续接校验复用。
- 抽取全局和工作区设置共用的同步独占文件锁协议；调用方各自保留设置读取、字段合并、错误回报和原子写入策略。
- 在 OpenCode JSONL 逐行解码时同时收集结构化终态和 provider 错误，不缓存解码记录，不重复解码相同 stdout。
- 每个位置扩展相邻单元回归测试，并在隔离编译副本中串行完成构建及目标测试，避免并行写共享 `dist/`。

## 非目标

- 不根据提交频率或补丁历史改动其它代码；不把必要的兼容或安全校验视为可删除的补丁。
- 不改变 UI、产品行为、权限、数据格式、CLI 协议、锁等待上限或任务调度。
- 不做全仓格式化、跨 CLI 解析器大改或无关问题修复。

## 风险与缓解

- 风险：合并校验时把未知容量误当空容量，或弱化组织停止/续接门禁。
- 缓解：复用现有非法根、异常读取、空/非空租约和组织清理回归。
- 风险：抽取锁协议改变跨窗口互斥、重试、权限或释放身份检查。
- 缓解：两个存储共用同一锁实现，保留 1500ms 上限、5ms 轮询、`wx`/`0600` 和 inode 身份校验。临界区结束后先关闭句柄，再核验身份并删除路径；协作进程在路径删除前仍见 `EEXIST`。先删除再关闭在 Windows 的非 POSIX 删除回退下可能令正常竞争收到 `EACCES`。路径核验和删除并非原子操作，本协议不保证抵抗非协作进程换路径。
- 风险：OpenCode 解析整理影响结构化最终回答、错误细节或纯文本回退。
- 缓解：保留 JSONL 逐行容错，并区分原始 JSON 终态和仅用于文本回退的 ANSI 清理结果；运行解析器与命令运行回归。
