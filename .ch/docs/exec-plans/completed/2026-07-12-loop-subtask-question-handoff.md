## 背景

Loop 子任务运行在独立对话标签页中，现有提示词只要求子任务在结束前写沟通文件，没有明确规定遇到需求不明、授权不足、依赖冲突或必须确认的问题时应如何收口。因此子任务可能直接在 assistant 回复中向用户提问，既不会继续推进，也绕过了主任务统一复核和沟通文件交接机制。

## 目标

1. 明确子任务一旦出现必须确认的问题，应立即停止实施并结束当前子任务。
2. 要求子任务把问题、事实、影响、可选方案和建议写入自己的沟通文件，由主任务读取并处理。
3. 禁止子任务在用户可见 assistant 回复中提问或复述待确认问题，只允许固定的中性收口文本。
4. 让主任务明确识别沟通文件中的待确认事项，并自行决策、继续派发或走 blocked 路径。

## 范围

- 更新 Loop 主任务和子任务模型提示词契约。
- 更新子任务沟通文件初始模板。
- 增加提示词与模板回归测试。
- 同步功能清单、能力规格和高复发踩坑记录。

## 非目标

- 不新增任务状态或改变现有 `end -> completed -> 唤醒主任务` 调度语义。
- 不隐藏正常子任务流式消息或回退 OpenCode 子任务对话气泡修复。
- 不通过问号等脆弱启发式拦截任意 assistant 内容。
- 不改变主任务向用户报告整体 blocked 的现有能力。

## 风险与缓解

- 风险：仅依赖自然语言约束，模型仍可能违反协议。
- 缓解：提供具体触发条件、强制步骤、沟通文件固定章节和唯一允许的最终收口文本，并用回归测试冻结完整契约。
- 风险：把可自行解决的小问题也当作阻塞，造成不必要结束。
- 缓解：提示词限定为“必须确认后才能继续”的问题；可由现有事实、仓库规则或授权范围内判断的问题仍应自行处理。
- 风险：与并发任务改动冲突。
- 缓解：并发 Loop 批次已结束；只逐 hunk 修改目标行，不回退工作区其他改动。
