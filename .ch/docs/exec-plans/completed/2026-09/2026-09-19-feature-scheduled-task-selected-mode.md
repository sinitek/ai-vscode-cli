## 本类型历史记录

### 背景

定时任务弹窗目前没有独立的模式选择，保存时只快照当前面板模式；到期后又按目标 CLI 当时的 `interactiveMode` 路由。用户需要在创建时显式选择 Vibe 或 Loop，并按选中模式已有配置执行。

### 目标

定时任务创建时可选择 Vibe / Loop；到期后按任务保存的模式路由到对应 Prompt 执行链，并使用该模式在创建时快照的配置。旧任务缺少模式字段时回退到目标 CLI 当前模式。

### 范围

- 定时任务弹窗增加 Vibe/Loop 选择器，默认当前面板模式。
- 保存时按选中模式快照对应配置。
- 到期执行优先使用任务保存的模式及对应配置，而不是覆盖为当时工作区模式。
- 任务列表展示选中模式；同步 i18n、测试、功能清单和 ontology。

### 非目标

- 不新增 cron / 重复执行。
- 不在弹窗内重复配置模型等细节，只复用选中模式已有配置。
- 不改变立即发送、Loop 自身调度语义。

### 验收标准

- [x] 定时任务弹窗可选择 Vibe、Loop，默认当前面板模式。

- [x] 到期后按任务选中模式进入 `runPrompt` / `runLoopPrompt`。

- 风险：旧任务没有保存模式，行为会变化。
