# 龙虾辩论升级为红蓝对抗模式

- 日期：2026-06-18
- 状态：completed
- 负责人：Codex

## 背景

当前 `debate_multi_agent` 已经具备群聊式辩论、主持人控场、最终共识汇总与后续子任务派发能力，但参与者角色语义仍偏通用“规划/审查参与者”。用户希望辩论模式本身就体现红蓝对抗：一方提出方案，另一方专门攻击、找漏洞，最终由裁判/主持人收束，而不是泛化的多角色讨论。

## 目标

将现有 `debate_multi_agent` 升级为更明确的红蓝对抗编排：

- 红队负责攻击方案假设、目标覆盖、证据链、边界场景、可行性、成本收益和可验证性；只有任务涉及代码、文件、权限、部署或流程执行时，才额外检查写入范围、并发冲突、越权修改、回滚/恢复失败等工程风险。
- 蓝队负责提出方案、回应质疑、修正设计与补足验收。
- 裁判/主持人负责控场、判断继续/收束/阻塞，并维持现有共识与派发链路。
- 现有任务记录、群聊面板、恢复/中止、子任务执行链路尽量复用，不新增顶层模式。

## 范围

- 修改辩论模式的角色定义、提示词、运行文案和共识/收束语义。
- 更新 `src/lobsterDebate.ts`、`src/extension.ts`、`src/webview/*` 中辩论相关文本和协议字段。
- 更新中英文国际化文案与产品/设计/能力事实来源文档。
- 补充或调整单元测试，覆盖红蓝角色归一化、文案、收束与 needs-review 语义。

## 非目标

- 不新增新的顶层 `InteractiveMode`。
- 不重写子任务执行器或主从执行链路。
- 不引入远端多智能体服务或额外持久化后端。

## 风险与缓解

- 风险：仅改文案不改协议，用户仍会把它理解成普通群聊。
  - 缓解：同步改角色命名、提示词、收束说明和文档事实来源。
- 风险：改动辩论语义时误伤主从模式。
  - 缓解：限制改动范围只落在 `debate_multi_agent` 分支与辩论文案。
