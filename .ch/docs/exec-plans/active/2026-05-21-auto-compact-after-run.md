# 执行后自动上下文压缩切换

- 日期：2026-05-21
- 状态：completed
- 负责人：Codex

## 背景

当前插件已经落地“执行前自动压缩上下文”能力，但最新需求要求将自动压缩时机从任务启动前改为任务执行后，并明确只有任务成功结束才触发，避免在开始前插入额外压缩步骤或在失败后折叠排障上下文。

## 目标

将已有会话的自动上下文压缩从“任务开始前”改为“任务成功结束后”，并同步 UI 文案、运行时事实来源文档与能力清单。

## 范围

- 调整 `src/extension.ts` 中自动压缩触发时机
- 同步 `src/webview/*` 面板状态与中英文文案
- 更新 `.ch/docs/` 中相关事实来源说明

## 非目标

- 不改手动“常用命令 -> 压缩上下文”行为
- 不新增第二套独立设置项
- 不重构上下文压缩底层实现

## 验收标准

- [x] 工具设置文案明确表达为“执行后自动压缩”
- [x] 已有会话任务仅在成功结束后触发自动压缩，而不是开始前
- [x] 任务中断或报错不触发自动压缩
- [x] 功能清单与运行时事实来源已同步

## 影响面

- 代码目录：`src/extension.ts`、`src/webview/`
- 文档目录：`.ch/docs/product-specs/`、`.ch/docs/references/`、`.ch/docs/design-docs/`
- 配置与脚本：工作区设置持久化字段兼容处理

## 风险与缓解

- 风险：任务收尾与自动压缩共用运行状态，可能导致结束事件和后置压缩互相覆盖
- 缓解：将后置压缩挂在任务真正收尾之后，并限制为成功结束场景；中断和失败直接跳过
- 风险：已有存量设置字段命名仍是 before run，直接改名会丢失用户配置
- 缓解：保留存储字段兼容，先只调整语义和展示文案

## 验证计划

- 最小相关验证：构建 TypeScript，确认运行编排和面板状态无类型错误
- 扩展验证：静态检查普通任务、龙虾子任务、手动压缩路径互不影响
