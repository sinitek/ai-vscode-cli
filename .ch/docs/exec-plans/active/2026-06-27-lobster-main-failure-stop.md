# Loop 主任务失败终止护栏

- 日期：2026-06-27
- 状态：in-progress
- 负责人：Codex

## 背景

用户反馈 Loop 任务在 AI 调用已经失败、子任务也接连失败后，主任务没有及时结束，仍可能继续派发后续子任务，甚至累计到几十个。当前预期是：如果主任务 AI 调用连续失败 5 次，应直接失败结束，而不是继续派发或自动恢复。

## 目标

确认该问题是否存在；若存在，则为 Loop 主任务增加明确的连续失败终止边界，并阻断失败后的自动继续派发。

## 范围

- Loop 主任务运行与恢复状态机
- 主任务 AI 调用失败计数与终止条件
- 自动恢复/继续入口的失败上限约束
- 最小必要测试与文档同步

## 非目标

- 不调整子任务现有 1 分钟间隔、最多 5 次自动重试策略
- 不改动普通 coding 任务 hidden retry 通用机制
- 不扩展新的 UI 配置项

## 验收标准

- [ ] Loop 主任务 AI 调用连续失败达到 5 次时，任务记录进入终止态，不再自动继续派发子任务
- [ ] 失败达到上限后，自动恢复入口不会再次唤醒该主任务
- [ ] 可继续入口与终止态行为一致，不把已达上限的主任务当成普通可继续任务
- [ ] 补充最小回归测试覆盖成功路径、失败累计路径、恢复阻断路径

## 影响面

- 代码目录：`src/extension.ts`、`src/test/`

- 配置与脚本：无新增配置

## 风险与缓解

- 风险：把用户手动“继续执行”的人工恢复也一起误拦截
- 缓解：区分自动恢复与任务终止态；仅在达到主任务失败上限后阻断自动恢复，并让任务明确进入人工复核/失败说明
