# 前端与体验层基线

当前仓库还未绑定具体前端技术栈。本页合并前端体验和 ToB 产品视角，作为真实前端出现前的轻量入口。

## 产品视角

- 先明确主要角色、关键成功路径、异常路径和验收方式。
- ToB 能力默认考虑权限、审计、配置、运营、集成和治理。
- 不把“做一个页面”“加一个字段”“支持导出”直接当成完整需求。

## 前端约束

- 如果未来项目引入主题系统，样式必须优先使用语义化主题能力。
- 页面、路由、组件、状态、接口按业务域组织。
- 体验层负责编排和表达，不复制领域规则。
- 可访问性、空态、错误态、加载态、权限态必须是默认考虑项。
- 前端不得绕过明确契约直接依赖数据库或未定义的后端内部结构。
- 每个前端子应用都应有自己的局部 `AGENTS.md` 和页面地图。
- 复杂表单和复杂工作流先定义状态机或步骤图，再谈页面细节。

## 验证思路

- 关键用户旅程要可自动化回归。
- 可视回归、截图、DOM 快照、控制台错误检查应逐步纳入能力建设。
