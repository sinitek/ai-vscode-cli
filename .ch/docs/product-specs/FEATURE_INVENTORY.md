# 功能总表

这个文件是当前仓库功能清单的**单一事实来源**。

Loop / Loop+ 连续子任务会话复用：主模型用 `continueFromSubtaskId` 选择来源；Loop+ 验收失败的关联修补项自动继承原子任务，控制重派复用原线程。关闭 Tab 后仍可按持久化 CLI/config/session 绑定恢复，同一来源或会话串行执行；独立任务新会话，缺失或不兼容绑定记录原因后新建。经典汇报驱动和 Loop+ 验收规则不变。实现见 `src/loopSubtaskSession.ts`、`src/extensionHost/loopOrchestration.ts`、`src/extensionHost/loopPlusRuntimeAdapter.ts`；回归见 `src/test/loop/loopSubtaskSession.test.ts`、`src/test/extensionHost/loopPlusRuntimeIntegration.test.ts`、`src/test/extensionHost/subtaskCliExecution.test.ts`；规则见 `.ch/docs/design-docs/loop-subtask-session-reuse.md`。

作为 starter，这里默认从空表开始；当首个真实能力进入规划或实现时，再新增条目。

经典 Loop 采用汇报驱动：主模型只拆分、派发、协调并信任子任务汇报判断完成，不检查实现、不亲自验收或测试。用户明确要求或项目既有规则要求的验收、测试、构建及任务完成后检查，必须另派独立子模型任务并根据汇报收口；均无要求时默认不做。子任务首次执行与续跑均加载真实工作区规则，自主实施，不额外强制设计或实施流程。`completed` 只需非空 `finalSummary`，历史验收/需求覆盖/轮次摘要字段可选兼容；轻量总结不虚构“验收通过”。Loop+（包括全栈模式）的隔离、事件驱动验收和完成门槛不变。实现见 `src/extensionHost/loopOrchestration.ts`、`src/extensionHost/promptRunRuntime.ts`、`src/extensionHost/promptExecutionShared.ts`、`src/loopTaskStore.ts`、`src/loopFinalSummary.ts`；回归见 `src/test/extensionHost/loopMainDecisionParsing.test.ts`、`src/test/extensionHost/promptExecutionShared.test.ts`、`src/test/extensionHost/subtaskCliExecution.test.ts`、`src/test/loop/loopTaskStore.test.ts`、`src/test/loop/loopFinalSummary.test.ts`。

工具设置当前 UI 采用“常规配置”“AI任务配置”“工作区”“自动修复”四个 Tab；历史保留天数和 CLI 工具开关归入“常规配置”，人工交互、人工交互超时、执行后自动压缩上下文、Loop 参数及 Loop+ 单次派发上限归入“AI任务配置”，CLI `spawn ENOENT` 归入“自动修复”；插件初始化会对尚未解析的裸命令自动执行一次同样的修复。

AI 对话面板的“使用说明”弹窗仅保留默认选中的“模式说明”页签，展示如何选择及 Vibe、Loop、Loop+、Graph 的适用场景和优点；不再展示“安装”页签、CLI 安装命令及环境变量清理说明。其他安装入口不受影响。实现见 `src/webview/viewContentHtml.ts`、`src/webview/viewContentScript/settingsAndOverlays.ts`；回归见 `src/test/webview/loopPlusModeHelp.test.ts`、`src/test/webview/cliPageStaticRenderCoverage.test.ts`。

AI 对话消息区在内容更新前距离底部不超过 75px 时自动置底；超过 75px 时保留当前阅读位置，可通过“回到底部”按钮恢复跟随。聊天搜索结果锚定时不自动置底。执行流面板保留独立的 50px 自动跟随阈值。

AI 对话最终答复及普通助手气泡中的 Markdown 表格显示完整单元格边框、表头底色和斑马行，颜色使用 VS Code 主题变量；宽表在气泡内横向滚动。Loop / Loop+ 群聊复用同一套表格样式。实现见 `src/webview/viewContentStyles/markdown.ts`、`src/webview/chatMarkdown.ts`；回归见 `src/test/webview/chatMarkdown.test.ts`。

Loop、Loop+ 和 Graph 子任务创建时，子会话只保留正常样式的用户提示词气泡，不再额外插入系统样式的提示词副本或启动说明。主任务会话的派发提示、进度、异常和完成消息保持不变；不清理已有历史消息。实现入口为 `src/extensionHost/loopOrchestration.ts`、`src/extensionHost/loopPlusRuntimeAdapter.ts` 和 `src/extensionHost/graphRuntime.ts`；回归验证为 `src/test/extensionHost/subtaskCliExecution.test.ts`、`src/test/extensionHost/loopPlusRuntimeIntegration.test.ts`。

所有 CLI（Codex、Claude、OpenCode、Grok、DSH、KimiCode、ZCode）的指令气泡统一不显示副标题：保留主标题、用途标签、折叠摘要和展开正文，完整命令与路径不丢失。ZCode 每回合（含新建、复用、恢复）应用当前模型及思考档位，合法 UI 选择优先于配置默认值；例如配置 max、UI high，原生模型选项和 thoughtLevel 均须为 high。面板使用会话公布的真实档位，不自动降级 max，不让配置回报覆盖已选择的 high；切换会话、模型、档案或 CLI 后不沿用旧广告。配置页可导入范例中独立思考力度统一 high，未提供独立力度的分组不新增参数；不改写能力枚举、历史测量或用户配置。实现与回归见 `src/webview/viewContentScript/traceRendering.ts`、`src/interactive/zcodeRunner.ts`、`src/extensionHost/interactiveTurnZcode.ts`、`src/test/interactive/zcodeRunner.test.ts`、`src/test/webview/clipagescriptruntimecoverage.test.ts`、`src/test/config/cliPageConfigCoverage.test.ts`。

配置页面所有 CLI 分组的内置范例均不包含 `subcoco`，原有该名称统一替换为 `default`。KimiCode 范例的 Provider 定义、模型引用、表单占位提示及无模型可复制时的新增模型回退 Provider 均使用 `default`；不迁移或改写用户已有配置。

Loop+ 输入区工具栏最左侧有原生复选框「全栈」，默认勾选，并按主配置持久化。勾选时模型行是「主-思考」和「子-全栈」，所有编码使用子-全栈的 CLI、档案、模型和思考力度；取消后才显示「子-后端」「子-前端」并按职责路由。非编码的 general 分析使用主模型完整配置，仍是独立子任务。编码不能回退主模型。每个可见角色标签右侧有问号，悬停或键盘聚焦立即显示说明；模型行下方不再展示「分析可用主模型，编码必须使用对应子模型」的路由提示文案。经典 Loop、Graph 和普通聊天不显示该开关，主标签仍是「主模型」。实现见 `src/loopPlusSubtaskMode.ts`、`src/subtaskCliRoute.ts`、`src/modelSelectionStore.ts`、`src/extensionHost/loopPlusOrchestration.ts`、`src/webview/viewContentHtml.ts`；回归见 `src/test/loop/loopPlusSubtaskMode.test.ts`、`src/test/webview/loopPlusFullstackMode.test.ts`。

Loop+ 主模型每次落地验收时，必须为每个完成事件、固定六项默认验收和已选择的附加验收给出不超过 50 字的证据型原因，语言按任务、证据和上下文选择，不强制中文；缺失或超长原因不落地。Loop+ 群聊验收结果气泡逐项展示通过/未通过及原因。实现见 `src/loopPlusDecision.ts`、`src/loopPlusAcceptancePlan.ts`、`src/extensionHost/loopPlusOrchestration.ts`、`src/extensionHost/loopPlusPromptBuilders.ts`；回归见 `src/test/loop/loopPlusDecision.test.ts`、`src/test/core/loopPlusAcceptancePlan.test.ts`、`src/test/extensionHost/loopPlusPromptBuilders.test.ts`。

配置中心应用配置档案时，同一 CLI 的运行时写入按请求顺序串行执行，Codex 的 `config.toml` 与 `auth.json` 必须来自同一档案；快速切换不得产生跨档案文件混合，写入后读回不一致时提示“未成功更新配置”。不同 CLI 分组可独立应用。实现见 `src/config/configService.ts`；回归见 `src/test/config/configService.test.ts`。

AI 对话面板读取 Codex 当前 `config.toml` 的根级 `model` 作为配置默认模型：有值时替代空值“默认”项，并与 `~/.sinitek_cli/models.json` 中的用户管理模型按大小写不敏感规则去重；用户显式选择优先，配置缺失或读取失败时保持旧行为。实现见 `src/cli/codexConfigModel.ts`、`src/extensionHost/cliModelSelectionStrategies.ts`、`src/extensionHost/modelSettings.ts`、`src/webview/viewContentScript/modelManager.ts`；回归见 `src/test/cli/codexConfigModel.test.ts`、`src/test/extensionHost/cliModelSelectionStrategies.test.ts`、`src/test/webview/grokmodelselection.test.ts`。

## 对话标签执行配置恢复

点击“重置会话”仅替换当前会话标签、清空新会话消息，不重置当前 CLI 分组所选的有效配置；配置应用尚未完成或刷新仍携带旧配置时，也保留用户选择及待应用状态。重置意图只用于同 CLI 的旧标签被空白新标签替换，后续普通标签切换仍恢复目标标签配置。实现见 `src/webview/viewContentScript/eventBindings.ts`、`src/webview/viewContentScript/modelAndPanelState.ts`；回归见 `src/test/webview/clipagescriptruntimecoverage.test.ts`、`src/test/session/sessionTabCliSwitch.test.ts`。

切换 AI 对话标签、自动切换到其他标签或打开已有会话时，底部配置随目标标签恢复：Loop / Loop+ 主标签沿用对应调度模式，恢复任务当前绑定的主配置、主模型、子 CLI、子配置和子模型；关闭当前标签并自动切换到相邻标签时也恢复目标标签配置；子标签使用 Vibe，并恢复该标签实际执行的模型。新用户消息持久化配置 ID、原始模型 ID、思考力度和 OpenCode variant 快照，普通会话也可恢复，不用历史展示名反推模型。已删除的配置或模型、缺少可靠快照的旧记录保持对应当前选择；模型不可用时不改其思考力度。快速切换或切换工作区时丢弃过期的模型恢复及消息刷新。实现见 `src/conversationTabConfiguration.ts`、`src/panelMessageHandlers/session.ts`、`src/extensionHost/sessionTabs.ts`；回归见 `src/test/session/conversationTabConfiguration.test.ts`、`src/test/session/sessionMessageHandlersCoreCoverage.test.ts`、`src/test/session/sessionTabCliSwitch.test.ts`、`src/test/extensionHost/openCodePromptRunTemplate.test.ts`。

对话 Tab 首次预载有效用户任务时持久化 `executionLocked` 与首个主模型快照；此后该 Tab 的 CLI 下拉仍可切换，当前 Tab 已执行过任务且当前 CLI 有 session ID 时先提示“切换其它 CLI 会丢失上下文，确定？”，取消保持原 CLI，确认后切换并沿用目标 CLI 会话映射；没有 session ID 时无需确认。主模型选择器保持可用，Webview 与 Panel 消息接受主模型和子模型切换，后续执行及消息执行快照使用新选择。已有会话初始化时会从 Tab 映射的任一会话用户消息迁移锁定状态；新建 Tab 不受其他 Tab 影响，切换到其他 Tab 仍可用。实现见 `src/sessionTabs.ts`、`src/extension.ts`、`src/panelMessageHandlers/session.ts`、`src/sessionMessageActions.ts`、`src/webview/viewContentScript/eventBindings.ts`、`src/webview/viewContentScript/modelManager.ts`；回归见 `src/test/session/conversationTabLock.test.ts`、`src/test/session/sessionMessageHandlersCoreCoverage.test.ts`、`src/test/webview/codexdualmodelwebview.test.ts`。

模型选择写入不受永久 `executionLocked` 限制；该锁仍只保护 CLI 切换旁路。回归见 `src/test/session/conversationTabModelSelection.test.ts`。

点击 Loop / Loop+ 主任务标签会打开该任务的群聊页面。标签已经选中时，再次点击或按 Enter / Space 同样打开。子任务标签、普通会话标签和关闭按钮不打开群聊。输入区“打开群聊”按钮仍然可用。实现见 `src/webview/viewContentScript/messageRendering.ts`；回归见 `src/test/webview/clipagescriptruntimecoverage.test.ts`。

## 更新规则

- 新增能力时新增一行。
- 修改已有能力时更新状态、角色、规格来源、测试状态和备注。
- 下线能力时不要直接删除，改成 `removed` 并保留历史说明。
- 如果一个功能变更无法直接链接到规格，至少要能链接到执行计划或设计文档。
- 不要让 README、聊天记录、任务单、临时表格分别维护不同版本的功能列表。

## 什么时候必须更新

- 新增用户可感知能力、后台能力、运维能力或平台能力。
- 修改已有能力的行为、权限、流程、入口、状态或适用角色。
- 能力进入暂停、废弃、替换、下线状态。
- 需求没有新增页面，但改变了导入导出、通知、审计、报表或批处理能力。

## 状态枚举

- `proposed`：已识别，但尚未进入实施
- `in-progress`：正在建设
- `active`：已经交付且当前生效
- `deprecated`：仍存在，但不建议继续使用
- `removed`：已下线，仅保留历史记录

## 维护边界

- 功能名描述用户或系统能力，不直接使用页面名或接口名。
- 测试状态只回答是否有基础自动化护栏，不替代测试报告。
- 执行计划应说明本次是否需要更新本表；收尾说明应记录实际变更项。
