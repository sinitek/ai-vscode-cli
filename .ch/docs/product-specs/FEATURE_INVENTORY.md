## AI 对话 Tab 状态与配置协调

- 状态：`active`（2026-11-11）。Tab 有真实运行信号时优先显示运行态，中间 trace/system 错误保留在消息中但不覆盖运行状态。每 Tab 记录宿主最新运行状态，`runStatus:end` 后迟到的新增/替换错误消息、trace 片段和自动重试排队提示不再重新标红；新用户消息、新运行或会话重置释放上一轮成功保护。明确的 `runStatus:error` 仍标记失败，未运行过的空闲错误仍可见，新运行和恢复输出沿用原有清理逻辑。前台与后台 Tab 隔离处理，不改变错误气泡或磁盘会话格式。
- 共享配置已有状态通过只读快照获取，面板刷新不获取配置写锁、不回写执行租约。首次初始化、配置应用/编辑和执行租约仍使用跨进程互斥锁；同进程同目录的事务顺序排队，不彼此轮询到超时。
- 读取到未就绪状态不视为配置可用；任务启动仍在互斥事务中核对所选档案及就绪状态。存活进程持有的写锁不按时间强拆，真实跨窗口写操作超时仍明确拒绝启动。
- 实现：`src/webview/viewContentScript/messageRendering.ts`、`src/config/sharedRuntimeConfig.ts`；回归：`src/test/webview/tabRunStatus.test.ts`、`src/test/webview/conversationtabsummarytooltip.test.ts`、`src/test/config/sharedRuntimeConfig.test.ts`。

## Loop / Loop+ 总体进度

- 状态：`active`（2026-11-08）。主模型在每次验收成功提交后评估总体完成度，任务记录保存 0–99 的模型判断值；补充需求可使进度重新校准。未成功提交的验收不更新进度，最终完成门禁成功后置为 100%，停止、暂停和续跑保留原值。
- 经典 Loop（2026-11-09）在一个批次全部结束、准备下一批次的有效主任务决策中返回 `progressPercent`，根据全部需求、子任务汇报与剩余工作判断 0–99% 总体进度，不按子任务数或批次数推算，不增加主模型验收。首次拆分从 0% 开始，最终完成设为 100%，停止、暂停和续跑保留 `loopProgressPercent`；与 Loop+ 的 `loopPlusProgressPercent` 独立保存。
- 两种模式的群聊副标题只显示任务 ID；左侧主任务成员标题显示“主任务 N%”，标题栏中止按钮左侧也展示较大字号进度。五档背景配色对应 [0,20)、[20,40)、[40,60)、[60,80)、[80,100]，使用 VS Code 主题语义色，窄屏保留进度与中止按钮相邻。缺失或非法历史值按 0% 展示，未完成记录最多显示 99%。

## Loop / Loop+ 每轮简单事项直办

- 每一轮均按复杂度、风险和验证需求判断，覆盖首次、补充需求、用户消息、继续、验收及收尾。目标明确、局部低风险、操作结果可直接确认，且用户与项目规则均无测试、构建或独立验收要求的简单事项，由主任务直接完成，不委派、不额外验收。不按操作类型、文件数或行数限制，不把复杂工作拆碎来规避流程。
- 不冲突的简单补充事项可在其它任务执行时处理；其它任务仍照常派发、等待或验收，不接管或修补已委派产物，不因子配置失败回退主模型编码，也不遗漏原始及补充要求。
- Loop+ 无运行、排队或待验收工作且无附加审查时，宿主接受 `directCompletion=true` 与完成结论组成的精简 `completed`，不要求验收/覆盖清单，不新增验收反馈；历史子任务不影响资格。其它完成门禁、用户消息队列和已派发工作验收保持不变。
- 实现：`src/loopDirectExecutionPolicy.ts`、`src/loopPlusDecision.ts`、`src/extensionHost/loopOrchestration.ts`、`src/extensionHost/loopPlusPromptBuilders.ts`、`src/extensionHost/loopPlusOrchestration.ts`。验证覆盖两种模式和所有提示阶段、简单补充事项、历史委派后的精简收口，以及开放任务/事件/附加审查的拒绝路径。

## Loop+ 成员验收气泡定位

- Loop+ 群聊中已有验收反馈的子任务成员可点击查看最近一次验收结果，不区分成功或失败；批量验收中的成员可定位同一气泡。点击或键盘激活后滚动并聚焦气泡，窄屏同时收起成员抽屉；减少动态效果偏好下立即定位。

- 成员最近一次可定位验收气泡属于群聊清理保护项，首次渲染和内容补丁同步更新成员入口与锚点；仍计入限额，必要时允许保护项超限，不删除 transcript 或改变调度。

## 每 Tab 聊天气泡显示限额

- 状态：已实现并通过针对性合并验收（2026-11-09）；全仓覆盖率、真实扩展宿主/CLI 与 Windows/Linux 未验证，详见归档计划。入口：工具设置 → AI任务配置；全局工具 `~/.sinitek_cli/settings.json` 的 `chatMessageLimit` 对各 Tab 分别生效，默认 500，整数范围 1–10000。有限数字及非空数字字符串向下取整后钳制；空值、空白字符串、非数字、非有限数或其它类型回退 500。

## Loop / Loop+ 随时补充需求

- 群聊「补充需求」弹窗不依赖主模型空闲；提交后入口始终可再次打开，不等待群聊刷新。可连续提交多条需求，按提交顺序持久化并显示在群聊中，不打断当前主模型或子任务调用，也不另起并发主模型提问。

- 复用“携宁 CLI 提醒”系统身份，正文为“【目录名 项目】 任务已完成，请返回编辑器中的 AI 对话面板查看结果。”，项目名来源与人工交互提醒一致，不含任务内容、完整路径或敏感信息。Windows 仅在后台请求任务栏闪烁；macOS 仍是系统通知，不新增 Dock 弹跳。Windows 两类通知使用不同 Tag，不互相覆盖。
- 完成提醒与人工交互共享窗口状态，不互相清除；多个完成事件可聚合一条通知，最近 512 个事件 ID 去重。完成图标提醒持续到恢复焦点或关闭完成窗口提醒设置；恢复焦点后不重放。前台完成立即通知，之后切后台不补发通知或闪烁；通知派发先于焦点恢复时的完成窗口状态清理，避免排队事件漏发。已投递通知仍可留在通知中心。

## VSIX 瘦身与平台定向导出

- 默认导出通用包，剔除开发临时页面、截图、构建 source map、SDK 类型声明和嵌套 Python 缓存，不删除 Claude 内置 CLI、WASM、图片处理或其他运行时能力。
- 模型导入所需的 `jsonc-parser` 显式声明为生产依赖；通用包及所有平台包均审计其包描述与 CommonJS 入口，缺少时阻止导出，避免安装后因缺少解析器无法激活扩展。
- 仓库 README 保留本地图片预览；导出时不依赖 GitHub/GitLab 地址推导，仅在 VSIX 内将已登记的介绍图改为当前版本的 Gallery HTTPS 地址，并注册标准可寻址截图资产，由市场随包托管。README、图片文件、HTTPS 引用和资产登记均通过 ZIP 审计；新增本地图需登记，缺图或遗漏转换阻止导出。详见打包运行手册。
- `python3 scripts/export_vscode_extension.py --target current`（Windows 可用 `python`）或显式平台值导出独立命名、带 VSIX target 标记的平台包；只裁剪其他平台的 ripgrep/sharp/libvips，缺少目标原生依赖时失败，不改变工作区依赖。支持范围与分发边界见 `.ch/docs/runbooks/local-development.md` 的“打包 VSIX”。
- 实现入口：`scripts/export_vscode_extension.py`、`scripts/vsix_target.js`、`.vscodeignore`；回归入口：`src/test/shared/vsixPackaging.test.ts`、`scripts/tests/test_export_vscode_extension.py`，并执行真实打包和 ZIP 审计。

## 更新规则

- 新增能力时新增一行。
- 修改已有能力时更新状态、角色、规格来源、测试状态和备注。
- 下线能力时不要直接删除，改成 `removed` 并保留历史说明。
- 如果一个功能变更无法直接链接到规格，至少要能链接到执行计划或设计文档。
- 不要让 README、聊天记录、任务单、临时表格分别维护不同版本的功能列表。

## 什么时候必须更新

- 新增用户可感知能力、后台能力、运维能力或平台能力。
- 修改已有能力的行为、权限、流程、入口、状态或适用角色。
- 能力进入暂停、废弃、替换、下线状态。
- 需求没有新增页面，但改变了导入导出、通知、审计、报表或批处理能力。

## 状态枚举

- `proposed`：已识别，但尚未进入实施
- `in-progress`：正在建设
- `active`：已经交付且当前生效
- `deprecated`：仍存在，但不建议继续使用
- `removed`：已下线，仅保留历史记录

## 维护边界

- 功能名描述用户或系统能力，不直接使用页面名或接口名。
- 测试状态只回答是否有基础自动化护栏，不替代测试报告。
- 执行计划应说明本次是否需要更新本表；收尾说明应记录实际变更项。
